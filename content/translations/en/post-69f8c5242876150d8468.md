## What Is Memory
Memory can store data. Before a program executes, **it must first be loaded into memory before the CPU can process it**—this eases the speed mismatch between the CPU and the hard disk.

In a multiprogramming environment, multiple programs execute concurrently in the system, which means the data of multiple programs needs to be placed in memory at the same time.
So how do we distinguish where each program's data is stored?

Memory contains many "small rooms," and each small room is a "**storage unit**."

Memory addresses start at 0, and **each address corresponds to one storage unit**.

If the computer is "**byte-addressed**," then **each storage unit is 1 byte** in size, i.e., 1B, i.e., 8 binary bits.

If a computer with a **16-bit word length is "word-addressed**," then **each storage unit is 1 word** in size; each word is **16 binary bits** in size.

Supplementary knowledge:

$2^{10} = 1K$

$2^{20} = 1M$

$2^{30} = 1G$

What does it mean when a phone/computer has 4GB of memory?

It means that this memory can store $4*2^{30}$ bytes.

If it is byte-addressed, that means there are $4*2^{30} = 2^{32}$ storage units.

$2^{32}$ addresses are needed to identify them one by one,
so addresses need to be represented with 32 binary bits ($0 \sim 2^{32}-1$).

### Concept of Memory Management

A computer **cannot place all user processes** and all the programs and data required by the system **into main memory**, so the operating system must **reasonably partition memory space and perform effective dynamic allocation**.

The concept of **memory management** is **the operating system's partitioning and dynamic allocation of memory**.

### Memory Management Functions

- **Allocation and reclamation of memory space**: the operating system completes **the allocation and management of main memory space**;
- Address translation: converting **logical addresses** into **the corresponding physical addresses**;
- **Expansion** of memory space: using **virtual storage technology** or automatic overlay technology to **logically expand main memory**;
- **Storage protection**: ensuring that **each job runs within its own storage space** without interfering with others.

### Logical Addresses and Physical Addresses
- Logical address: the address specified in the instructions generated after the program is compiled and linked is a logical address (relative address), i.e., an address relative to the process's starting address;

## Basic Principles of Process Execution

Turning a user's **source program into a program that can execute in memory** usually requires the following steps:
- **Compilation**: the compiler compiles the user's source code into several object modules; (translating a high-level language into machine language)
- **Linking**: the linker connects a set of compiled object modules and the required library functions together to form a complete load module; (generating a load module from object modules, forming complete logical addresses after linking)
- **Loading**: the loader loads the load module into memory for execution, forming physical addresses after loading.

### Three Linking Methods
Programs can be linked in the following three ways:
- **Static linking**: before the program runs, the object modules and the library functions they require are first linked into a complete executable file (load module), which is then no longer split apart;
- **Load-time dynamic linking**: when the object modules are loaded into memory, linking is performed while loading;
- **Run-time dynamic linking**: an object module is linked only when the program needs it during execution. Its advantages are that it is easy to modify and update, and it facilitates sharing of object modules.

### Three Loading Methods
When load modules are loaded into memory, there are the following three methods:
- **Absolute loading** (single-program stage): at compile time, if it is known where in memory the program will be placed, the compiler generates object code with absolute physical addresses.
The loader loads the program and data into memory according to the addresses in the load module.
- **Static relocatable loading** (early multiprogramming batch systems): **compiled modules** need to be loaded contiguously into memory, but **their physical addresses in memory can differ from their logical addresses**, and a certain offset may exist.
For example, if the logical address is 0-100, it can be stored in memory units 100-200, and an offset of 100 needs to be set.
A characteristic of static relocation is that when a job is loaded into memory, **all the memory space it requires must be allocated**; if there is not enough memory, the job cannot be loaded.
**It also needs to be allocated contiguous storage space**; otherwise, it cannot be found through the offset.
Now the absolute address of the job in memory can be obtained through the job's **logical address + offset**.
- **Dynamic run-time loading** (modern operating systems): **different modules** can be loaded at **different memory addresses**, and **different modules do not need to be contiguous**, but **the same module must still be stored contiguously**.
For the same module, **a relocation register needs to be set**, and **the value in each module's relocation register** is the corresponding **offset**.
The loader will load the module into memory, but **will not immediately convert the relative addresses of the load module into absolute addresses**; instead, it **defers this address conversion until the program actually executes**.
**The program can be allocated to non-contiguous storage areas**.
