## The Role of Interrupts
Two kinds of programs run on the CPU: one is the **operating system kernel program**, and the other is **application programs**.

Under appropriate circumstances, the operating system kernel will voluntarily hand over the right to use the CPU to an application program.

An "interrupt" is **the only way for the operating system kernel to take back the right to use the CPU**.

Without the "interrupt" mechanism, once an application program starts running on the CPU, the CPU will keep running that application program (no interrupts, no concurrency).

## Types of Interrupts

In a broad sense, interrupts include two types: internal interrupts (also called exceptions) and external interrupts (interrupts in the narrow sense).

Internal interrupts are **related to the currently executing instruction**, and the interrupt signal comes from **inside the CPU**.

External interrupts are **unrelated to the currently executing instruction**, and the interrupt signal comes from **outside the CPU**.

### Types of internal interrupts (exceptions):
1. Trap: triggered by a trap instruction, and deliberately triggered by the application program;
2. Fault: caused by an error condition and may be fixed by the kernel program. After the kernel program fixes the fault, it will return the right to use the CPU to the application program so that it can continue executing. Examples include page faults;
3. Abort: caused by a fatal error that the kernel program cannot fix, so the CPU usage right is generally not returned to the application program that caused the abort; instead, the application program is terminated directly. Examples include integer division by zero and illegal use of privileged instructions.

### Types of external interrupts:
These include clock interrupts, I/O interrupts, and so on.


### Examples of internal interrupts (exceptions)

**Termination instruction**: If the currently executing instruction is illegal, an interrupt signal will be triggered.

**Trap instruction**: Sometimes an application program wants to request a service from the operating system kernel. At this point it executes a special instruction—the trap instruction—which triggers an internal interrupt signal.

Executing the "trap instruction" means that the application program voluntarily returns CPU control to the operating system kernel. "System calls" are completed through trap instructions.

### Examples of external interrupts

**At the end of each instruction execution**, the CPU routinely checks whether there is an external interrupt signal.

Clock interrupt: The clock component sends a clock interrupt signal to the CPU every time slice (e.g., 50 ms). The process of a clock interrupt is as follows:

1. During the execution of application program 1, when the execution time reaches one time slice, the time allocated to that application program by the CPU is exhausted.
2. At this point, the clock component sends a clock interrupt signal to the CPU. The CPU switches to kernel mode and executes the kernel program that handles the clock interrupt. The operating system kernel decides to let application program 2 run on the CPU next.
3. Next, it switches to user mode to execute application program 2, and so on.

I/O interrupt: An interrupt signal sent by an input/output device. When an input/output task is completed, an interrupt signal is sent to the CPU.

## Basic Principles of the Interrupt Mechanism

Different interrupt signals need to be handled by different interrupt handlers. After the CPU detects an interrupt signal, it looks up the "**interrupt vector table**" according to the type of the interrupt signal, so as to find the memory location where the corresponding interrupt handler is stored.
