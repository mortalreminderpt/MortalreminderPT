The main purpose of the data link layer is to achieve reliable and efficient communication of "frames" between two adjacent machines.  
- **Handle transmission errors**: Ensure the integrity of data transmission.  
- **Flow control**: Regulate the speed difference between the sender and receiver to avoid buffer overflow or transmission interruption.  

## Functions of the Data Link Layer

1. **Provide a well-defined service interface to the network layer**  
   - Receive packets from the network layer, construct data frames, and transmit them.  
   - Ensure that the network layer can transmit data on a reliable basis.  

2. **Handle transmission errors**  
   - Detect and correct errors that may be introduced by the physical layer, ensuring the integrity of data frames.  

3. **Flow Regulation**  
   - Regulate the data flow between the sender and receiver to avoid data loss or buffer overflow.  

4. **Other specific functions**  
   - Flow control: Control the frame transmission rate to match the receiver's capability.  
   - Error detection and correction: Detect and correct errors during transmission.  

## Framing

### What is Framing
Framing is the process of dividing a continuous bit stream into independent, manageable data units called "frames".  
**Purpose**: To provide reliability for data transmission on top of an unreliable physical layer.  

### Framing Methods

1. **Character Count**  
   - Record the number of characters in the frame in the frame header.  
   - Drawback: If the frame header data is corrupted, subsequent data frames cannot be parsed correctly (chain reaction).  

2. **Byte Stuffing**  
   - Use a special "flag byte" to mark the start and end of each frame.  
   - If the flag byte appears in the data, perform byte stuffing to avoid confusion.  

3. **Bit Stuffing**  
   - Frames start and end with a special bit pattern (01111110).  
   - If five consecutive 1s appear in the data, insert a 0 to avoid conflict with the flag.  

## Error Detection and Correction

### Error Correction
- Suitable for transmission media with high noise (such as wireless channels).  
- Can repair data without retransmission, suitable for unreliable connection environments.  

### Error Detection
- Suitable for transmission media with low error rates (such as high-quality wired connections).  
- More efficient but requires data retransmission.  

The key to error detection and correction lies in assuming the maximum number of errors that can occur.

## Hamming Distance

Hamming distance refers to the number of positions at which the corresponding characters of two strings differ.  

- The data length is $ n $ bits, and $ k $ check bits are added through encoding to form a codeword of $ n+k $ bits.  
- **d+1**: Can detect up to d errors.  
- **2d+1**: Can correct up to d errors.  

## Error Correction Method: Hamming Code

- The number of check bits is related to the data bit length; at least $ k $ check bits are required.  
- Check bits are allocated according to specific rules, and only 1-bit errors can be corrected.  

## Error Detection Methods

1. **Parity Check**  
   - Count the number of 1s in the data and add a parity bit.  
   - The Hamming distance is 2; it can detect 1-bit errors but cannot correct them.  

2. **Internet Checksum**  
   - A checksum based on 16-bit words.  
   - The Hamming distance is 2, suitable for detecting 1-bit errors.  

3. **CRC**  
   - A more powerful detection method, typically using a 32-bit CRC.  
   - The Hamming distance is about 4, and it can detect and even partially correct multiple errors.  

## Comparison of Error Detection Methods

| Method              | Check Bit Length | Hamming Distance | Capability                         |
|-------------------|------------|----------|------------------------------|
| Parity | 1 bit        | 2        | Detects 1-bit errors                |
| Checksum | 16 bits       | 2        | Detects 1-bit errors                |
| CRC               | 32 bits       | 4        | Detects multiple errors and may partially correct them   |

## Flow Control

### Flow Control Problem
When the sender is faster than the receiver's processing speed, buffer overflow or data loss may occur.  

### Flow Control Methods
1. **Feedback-based Flow Control**  
   - The receiver sends control signals to the sender to regulate the flow.  

2. **Rate-based Flow Control**  
   - The sender transmits data at a preset rate without requiring feedback from the receiver.  

### Stop and Wait Protocol
- After sending each frame, the sender must wait for an acknowledgment (ACK) from the receiver.  

### Sliding Window Protocol
Allows the sender to send multiple frames at the same time, improving transmission efficiency.  

1. **Go-Back-N**  
   - The sender window size is $ N $, and the receiver window size is 1.  
   - When an error occurs, retransmit the erroneous frame and all subsequent frames.  

2. **Selective Repeat**  
   - The receiver window can receive frames at any position, and when an error occurs, only the specific lost frame is retransmitted.  
   - Negative acknowledgment (NAK) is used to indicate the specific error location.  

## Link Utilization

- **Transmission time (Tf)**: Related to frame size and bandwidth.  
- **Propagation time (Tp)**: Related to physical distance.  

Optimizing link utilization requires balancing these factors, for example, maximum utilization is achieved when $ Tf = 2Tp $.

## Summary

The data link layer plays a key role in computer networking:  
- Provides reliable frame transmission services.  
- Implements effective error detection and correction.  
- Manages communication between adjacent nodes.  
- Provides a robust interface for the network layer, improving the communication efficiency and reliability of the entire network.
