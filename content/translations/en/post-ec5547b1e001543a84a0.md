The main function of process control is to implement effective management of all processes in the system. It has functions such as creating new processes, terminating existing processes, and realizing process state transitions.

Simplified understanding: process control is about realizing process state transitions.

## Primitives

### Why must the process control (state transition) procedure be done "in one go"?

Suppose the event that process 2 is waiting for occurs at this moment. Then, in the operating system, the kernel program responsible for process control needs to do at least two things:
1. Set the state of PCB2 to 1
2. Move PCB2 from the blocked queue to the ready queue

If an interrupt signal is received after completing the first step, then PCB2 has state=1, but it is placed in the blocked queue.

If it cannot be done "in one go", it may lead to inconsistency in the information of some key data structures in the operating system, which will affect the operating system's other management work.

### Principle of primitive execution

The execution of a **primitive** is **atomic**, that is, the execution process can only be done in one go, and **interruption is not allowed** during it.
Atomicity can be achieved using the two **privileged instructions** "**disable interrupts** instruction" and "**enable interrupts** instruction".

Under normal circumstances, **after executing each instruction**, the CPU will routinely **check whether there is an interrupt signal** that needs to be handled.
If there is, it pauses the current program and switches to executing the corresponding interrupt handler.

After the CPU executes the **disable interrupts instruction**, it no longer routinely checks for interrupt signals, and only resumes checking after executing the **enable interrupts instruction**.

In this way, the sequence of instructions between disabling interrupts and enabling interrupts cannot be interrupted, thus achieving "atomicity".

## Process control primitives

No matter which process control primitive it is, there are only three types of things to do:
1. Update the information in the PCB (modify the process state, save/restore the running environment);
2. Insert the PCB into the appropriate queue;
3. Allocate/reclaim resources.

### Running environment information

During the execution of program instructions, many "registers" are set in the CPU to store certain data needed during program execution, such as:
- PSW: Program Status Word register
- PC: Program Counter, stores the address of the next instruction
- IR: Instruction Register, stores the instruction currently being executed
- General-purpose registers: store other necessary information

During the sequential execution of instructions, many intermediate results are placed in various registers. For example, when executing the following code:

```c
/* ... */
int x = 1;
x++;
/* ... */
```

After instruction 3 is executed, another process starts running on the CPU. Since the other process will also use various registers during its execution, the CPU register data will be overwritten.

To solve this problem, when switching processes, first **save this process's running environment in the PCB** (save some necessary register information). When the original process is put into operation again, **its running environment can be restored through the PCB**.
