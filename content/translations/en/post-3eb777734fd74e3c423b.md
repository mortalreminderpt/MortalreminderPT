**Role of the Network Layer**  
- **Connecting different networks (internetworking)**: Enables communication between multiple networks.  
- **Routing**: Determines the best path for data transmission.  

---

### **Connectionless vs. Connection-Oriented**  

#### **Connectionless (Datagram)**  
- Similar to sending a letter; each packet is independent and takes its own path.  
- No path needs to be established in advance; packets may arrive out of order.  
- Example: Data transmission on the Internet.  

#### **Connection-Oriented (Virtual-Circuit)**  
- Similar to making a phone call; a stable path is established before communication begins.  
- All packets follow the same path, guaranteeing in-order arrival.  
- Example: Video conferencing or VoIP calls.  

| **Comparison**               | **Datagram**                                    | **Virtual-Circuit**                            |
|-------------------------|------------------------------------------------|-----------------------------------------------|
| **Path establishment**           | No connection needs to be established.                               | A connection needs to be established.                                 |
| **Addressing**               | Each packet requires full address information.                 | Packets only need a short virtual circuit identifier.                 |
| **Routing**               | Each packet independently determines its path.                         | The path is determined in advance.                               |
| **Impact of router failure**   | Only affects the current packet transmission.                         | Interrupts ongoing communication.                         |
| **Quality of Service**           | QoS is difficult to guarantee.                               | QoS is easier to guarantee.                           |
| **Congestion control**           | Congestion is difficult to manage.                                   | Congestion is easier to control after resource reservation.                       |

**Summary**:  
- Virtual-Circuit provides better QoS and congestion control.  
- Datagram is flexible and connectionless, but requires larger routing tables and additional overhead.  
- **The IP protocol uses a Datagram network.**  

---

### **Tunneling**  
- Used when the source and destination are on the same network but other networks lie in between.  
- The source packet is encapsulated in another packet for transmission.  

---

### **Fragmentation**  
- Splitting large packets into smaller fragments to fit the network's Maximum Transmission Unit (MTU).

**Fragmentation types**:  
1. **Transparent**: Fragmentation and reassembly occur at every network traversed.  
2. **Non-Transparent**: Packets are reassembled only at the destination.  

---

### **IPv4 Datagram Structure**  

| **Field**               | **Description**                                        |
|-------------------------|------------------------------------------------|
| **Version**             | 4 bits, indicates the protocol version (IPv4).                    |
| **IHL**                 | Header length, in units of 32 bits (minimum 5, maximum 15).         |
| **Differentiated Services** | 8 bits, used to define QoS or priority.                  |
| **Total Length**        | 16 bits, total packet size (maximum 65535 bytes).          |
| **Identification**      | 16 bits, identifies the packet and is used for fragment reassembly.               |
| **Flags (DF, MF)**      | Controls fragmentation behavior.                                  |
| **Fragment Offset**     | 13 bits, the position of the current fragment within the packet.               |
| **TTL**                 | 8 bits, the packet's time to live (hops or seconds).            |
| **Protocol**            | 8 bits, indicates the protocol (e.g., TCP or UDP).                 |
| **Header Checksum**     | 16 bits, verifies only the integrity of the header.                     |
| **Source Address**      | 32 bits, the sender's IP address.                         |
| **Destination Address** | 32 bits, the receiver's IP address.                         |
| **Options**             | Optional fields, such as timestamps or routing control.               |

- **Header size**:  
  - Minimum: 20 bytes (IHL=5).  
  - Maximum: 60 bytes (IHL=15, including options).

### **IP Addresses and Subnets**  

#### **IP Address**  
- Represents the location of a device on the network, e.g., `192.168.0.1`.  

#### **Subnet Mask**  
- Distinguishes the network portion from the host portion, e.g., `192.168.1.0/24` indicates a 24-bit network portion.  

#### **Classful Addressing**  
- Divides IP addresses into fixed blocks:  
  - **Class A**: Large-scale networks.  
  - **Class B**: Medium-scale networks.  
  - **Class C**: Small-scale networks.  

#### **CIDR (Classless Inter-Domain Routing)**  
- Allows flexible allocation of address blocks, e.g., `/24`.  

**Example**:  
- The subnet `135.46.56.0/21` can hold at most \( 2^{11} = 2048 \) addresses.  

---

### **NAT (Network Address Translation)**  
- Represents multiple internal IP addresses with a single external IP address, conserving IP address space.  

**Conflict with the five-layer architecture**:  
- Breaks layer transparency: NAT modifies data at the network layer (IP addresses) and the transport layer (port numbers).  
- Source addresses and ports are changed, affecting end-to-end communication transparency.  

---

### **ICP（Internet Control Protocols）**  

1. **ICMP (Internet Control Message Protocol)**:  
   - Reports errors and provides diagnostics (such as ping and traceroute).  

2. **ARP (Address Resolution Protocol)**:  
   - Maps IP addresses to MAC addresses for local communication.  

3. **DHCP (Dynamic Host Configuration Protocol)**:  
   - Dynamically assigns IP addresses to devices so they can join the network.
