## The Concept of Contiguous Allocation

The allocation and reclamation of memory space includes **contiguous allocation management methods** and **non-contiguous allocation management methods**.

**Contiguous allocation**: means that what is allocated to a user process must be a **contiguous memory space**.

## Single Contiguous Allocation

In the single contiguous allocation method, memory is divided into a **system area** and a **user area**.
The system area is usually located in the low-address part of memory and is used to store operating system-related data; the user area is used to store user process-related data.
There can be **only one user program** in memory, and the user program monopolizes the entire user area space.

- Advantages: simple to implement; **no external fragmentation**; overlay technology can be used to expand memory; memory protection does not necessarily need to be adopted (such as the early PC operating system MS-DOS).
- Disadvantages: can only be used in single-user, single-task operating systems; **has internal fragmentation**; a large part of the user area is idle, and memory utilization is extremely low.

Internal fragmentation: in the memory area allocated to a process, if some parts are not used, they are "internal fragmentation".

## Fixed Partition Allocation

In the 1960s, systems supporting multiprogramming appeared.
In order to load multiple programs into memory and prevent these programs from interfering with each other, the **entire user space** is divided into **several fixed-size partitions**.
**Only one job is loaded into each partition**, thus forming the earliest and simplest memory management method capable of running multiple programs.

Fixed partition allocation has two modes of partitioning: equal partition sizes and unequal partition sizes, as shown in the figure below:

- Equal partition sizes: lacks flexibility, but is **very suitable for situations where one computer controls multiple identical objects** (for example, if a steel plant has n identical steelmaking furnaces, memory can be divided into n equal-sized areas to store n steelmaking furnace control programs);
- Unequal partition sizes: increases flexibility and can meet the needs of processes of different sizes.
Partitioning is based on the sizes of jobs that often run in the system. (For example, divide multiple small partitions, an appropriate number of medium partitions, and a small number of large partitions)

The operating system needs to establish a data structure — a **partition description table** — to implement the allocation and reclamation of each partition.
Each table entry corresponds to a partition and is usually arranged by partition size.
Each table entry includes the corresponding partition's **size, starting address, and status** (whether it has been allocated).

|Partition No.|Size (MB)|Starting Address (M)|Allocation Status|
|--|--|--|--|
|1|2|8|Unallocated|
|2|2|10|Unallocated|
|3|4|12|Allocated|
|...|...|...|...|

When a user program is to be loaded into memory, the operating system kernel program searches the table according to the size of the user program, finds an unallocated partition that can satisfy the size, allocates it to the program, and then changes the status to "Allocated".
- Advantages: simple to implement, **no external fragmentation**.
- Disadvantages:
  1. When the user program is too large, all partitions may be unable to meet the requirement; in this case, overlay technology has to be used to solve it, but this will reduce performance; 
  2. **Internal fragmentation will be generated**, and memory utilization is low.

## Dynamic Partition Allocation

**Dynamic partition allocation** is also called **variable partition allocation**.
This allocation method **does not divide memory partitions in advance**; instead, when a process is loaded into memory, it **dynamically establishes partitions according to the size of the process**, and makes **the partition size exactly fit the needs of the process**.
Therefore, the size and number of system partitions are variable. (Assume a computer has 64MB of memory, an 8MB system area, and a total user area of 56MB)

### Free Partition Table and Free Partition Chain
The system can use two data structures, the free partition table or the free partition chain, to record memory usage:
- Free partition table: each free partition corresponds to one table entry. The table entry contains information such as the partition number, partition size, and partition starting address;
- Free partition chain: the beginning and end of each partition are respectively provided with a forward pointer and a backward pointer. The beginning can also record information such as the partition size.

### Dynamic Partition Allocation Algorithms
When loading a new job into memory, a partition must be selected from the free partition table (or free partition chain) according to a certain **dynamic partition allocation algorithm** and allocated to the job.
Because allocation algorithms have a great impact on system performance, people have studied them extensively.

### Partition Reclamation
1. If there is an adjacent free partition after the reclaimed area, merge the two adjacent free partitions into one;
2. If there is an adjacent free partition before the reclaimed area, merge the two adjacent free partitions into one;
3. If there is an adjacent free partition both before and after the reclaimed area, merge the three adjacent free partitions into one;
4. If there is no adjacent free partition before or after the reclaimed area, add a new table entry.

### Internal Fragmentation and External Fragmentation

Dynamic partition allocation **has no internal fragmentation**, but **has external fragmentation**.

- **Internal fragmentation**: in the memory area allocated to a process, if some parts are not used.
- **External fragmentation**: refers to some free partitions in memory that are too small to be used.

If the total amount of free space in memory could originally satisfy the requirements of a process, but because the process needs a whole contiguous block of memory space, these "fragments" cannot satisfy the process's requirements.
