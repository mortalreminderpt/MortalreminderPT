## Single Flag Method

Algorithm idea: Between two processes, one process, **after finishing access to the critical section**, will **transfer the permission** to use the critical section to the other process.
That is, the permission for each process to enter the critical section can only be granted by the other process.

```c
int turn = 0; // turn表示当前允许进入临界区的进程号

/* P0进程 */
while (turn != 0); // 1.进入区
critical section; // 2.临界区
turn = 1; // 3.退出区
remainder section; // 4.剩余区

/* P1进程 */
while (turn != 1); // 5.进入区
critical section; // 6.临界区
turn = 0; // 7.退出区
remainder section; // 8.剩余区
```

The initial value of turn is 0, meaning that at the beginning only process O is allowed to enter the critical section.

If P1 runs on the processor first, it will remain stuck at 5.
Until P1's time slice is used up and scheduling occurs, switching P0 to run on the processor.
Code 1 will not block P0; P0 can access the critical section normally, and even if it switches back to P1 during P0's access to the critical section, P1 will still remain stuck at 5.

Only after P0 changes turn to 1 in the exit section can P1 enter the critical section.
Therefore, this algorithm **can achieve "at most one process is allowed to access the critical section at any given time"**.

Drawback:
Access can only alternate in the order P0->P1->P0->P1.
The problem brought by this mandatory "alternating access" is that if the process currently allowed to enter the critical section is P0, and P0 never accesses the critical section, then although the critical section is idle at this time, P1 is not allowed to access it.

Therefore, the main problem of the **single flag method** is: **it violates the "idle let in" principle.**

## Two-Flag Check-First Method
Algorithm idea: Set a Boolean array `flag[0]`, where each element is used to **mark each process's intention to enter the critical section.**
For example, `flag[0]=ture` means that process 0, P0, now wants to enter the critical section.
Before entering the critical section, each process first checks whether any other process wants to enter the critical section; if not, it sets its own corresponding flag `flag[i]` to `true`, and then begins accessing the critical section.

```c 
bool flag[2]; // 表示进入临界区意愿的数组
flag[0] = false;
flag[1] = false;

/* P0进程 */
while (flag[1]); // 1.
flag[0] = true; // 2.修改标记为想要进入临界区
critical section; // 3.临界区
flag[0] = false; // 4.退出区
remainder section; 

/* P1进程 */
while (flag[0]); // 5.
flag[1] = true; // 6.修改标记为想要进入临界区
critical section; // 7.临界区
flag[1] = false; // 8.退出区
remainder section; 
```

If executed in the order 152637, P0 and P1 will access the critical section at the same time.

Therefore, the main problem of the **two-flag check-first method** is: **it violates the "busy then wait" principle.**

The reason is that the two operations of "checking" and "locking" in the **entry section** are **not completed in one uninterrupted step**. A process switch may occur after "checking" and before "locking".

## Two-Flag Lock-First Method

Algorithm idea: A revised version of the two-flag check-first method.
The problem with the previous algorithm was that it "checks" first and then "locks", but these two operations cannot be completed in one uninterrupted step, which led to the problem of two processes entering the critical section at the same time.
Therefore, people came up with the method of "locking" first and then "checking" to avoid the above problem.

```c 
bool flag[2]; // 表示进入临界区意愿的数组
flag[0] = false;
flag[1] = false;

/* P0进程 */
flag[0] = true; // 1.修改标记为想要进入临界区
while (flag[1]); // 2.如果P1也想进入临界区，则P0循环等待
critical section; // 3.临界区
flag[0] = false; // 4.退出区
remainder section; 

/* P1进程 */
flag[1] = true; // 5.修改标记为想要进入临界区
while (flag[0]); // 6.如果P0也想进入临界区，则P1循环等待
critical section; // 7.临界区
flag[1] = false; // 8.退出区
remainder section; 
```

If executed in the order 1526, neither P0 nor P1 will be able to enter the critical section.

Therefore, although the **two-flag lock-first method** **solves the "busy then wait" problem**, it **violates the "idle let in" and "bounded waiting" principles**, and will **cause "starvation"** because each process may be unable to access the critical resource for a long time.

## Peterson's Algorithm

Algorithm idea: Combine the ideas of the two-flag method and the single flag method. If both sides are competing to enter the critical section, the processes can try to yield.

```c 
bool flag[2]; // 表示进入临界区意愿的数组
int turn = 0; // turn 表示优先让哪个线程进入临界区
flag[0] = false;
flag[1] = false;

/* P0进程 */
flag[0] = true; // 1.进入区，表示自己想要进入临界区
turn = 1; // 2.进入区，表示可以优先让对方进入临界区
while (flag[1] && turn == 1); // 3.进入区，如果对方想进且最后一次是自己谦让则进行循环等待
critical section; // 4.临界区
flag[0] = false; // 5.退出区，表示自己不想访问临界区
remainder section; 

/* P1进程 */
flag[1] = true; // 6.进入区，表示自己想要进入临界区
turn = 0; // 7.进入区，可以优先让对方进入临界区
while (flag[0] && turn == 0); // 8.进入区，如果对方想进且最后一次是自己谦让则进行循环等待
critical section; // 9.临界区
flag[1] = false; // 10.退出区，表示自己不想访问临界区
remainder section; 
```

**Peterson's algorithm** solves the process mutual exclusion problem using a software method, and **follows the three principles of idle let in, busy then wait, and bounded waiting**, but it still **does not follow the principle of yielding while waiting.**

Compared with the previous three software solutions, Peterson's algorithm is the best, but it is still not good enough.
