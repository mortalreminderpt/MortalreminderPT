## What Is Deadlock

In a concurrent environment, a phenomenon in which processes, due to competing for resources, **wait for the resources held by each other, causing all processes to block and none to be able to move forward** is called "deadlock."
Once a deadlock occurs, unless there is external interference, none of these processes will be able to move forward.

## Deadlock, Starvation, and Infinite Loops

- Deadlock: A phenomenon in which processes wait for the resources held by each other, causing all processes to block and none to be able to move forward.
- Starvation: A phenomenon in which a process cannot move forward because it has long been unable to obtain the resources it wants. For example, in the Shortest Process First (SPF) algorithm, if short processes keep arriving continuously, long processes will never get the processor, resulting in "starvation" of long processes.
- Infinite loop: A phenomenon in which a process cannot escape a certain loop during execution. Sometimes this is caused by a program logic bug, and sometimes it is intentionally designed by the programmer.

## Necessary Conditions for Deadlock

A deadlock can occur only when the following four conditions are all satisfied at the same time; if any one of them does not hold, deadlock will not occur:
- **Mutual exclusion condition**: Only contention for resources that must be used mutually exclusively can lead to deadlock (such as the philosophers' chopsticks or a printer device). Resources that can be used by multiple processes at the same time, such as memory and speakers, will not cause deadlock (because processes do not need to block and wait for such resources);
- **No preemption condition**: Resources already obtained by a process **cannot be forcibly taken away by other processes** before they are used up; they can only be released voluntarily;
- **Request and hold condition**: A process **already holds at least one resource**, but requests new resources, and those resources are occupied by other processes. At this point, **the requesting process is blocked**, but it **keeps holding the resources it already has**.
- **Circular wait condition**: There exists a circular waiting chain of process resources, in which the resource already obtained by each process in the chain is simultaneously requested by the next process.

**Note! A deadlock necessarily involves circular waiting, but circular waiting does not necessarily mean deadlock** (circular waiting is a necessary but not sufficient condition for deadlock).

That is, if the **number of resources of the same type** (replaceable resources) is greater than 1, then even if there is circular waiting, deadlock may not occur.
But if there is only one resource of each type in the system, then circular waiting is a necessary and sufficient condition for deadlock.

## When Deadlock Occurs

1. Competition for system resources. Competition among processes for non-preemptible resources (such as printers) may cause deadlock, whereas competition for preemptible resources (CPU) will not cause deadlock.
2. Improper process advancement order. Improper order of requesting and releasing resources can also lead to deadlock. For example, concurrently executing processes P1 and P2 respectively request and occupy resources R1 and R2, after which process P1 then requests resource R2, while process P2 requests resource R1. The two will block because the resources they request are occupied by each other, thus causing deadlock.
3. Improper use of semaphores can also cause deadlock. For example, in the producer-consumer problem, if the P operation for mutual exclusion is placed before the P operation for synchronization, deadlock may occur. (Mutual exclusion semaphores and synchronization semaphores can also be regarded as a kind of abstract system resource.)

In short, unreasonable allocation of non-preemptible resources may lead to deadlock.

## Deadlock Handling Strategies

1. Deadlock prevention. Break one or several of the four necessary conditions for deadlock;
2. Deadlock avoidance. Use some method to prevent the system from entering an unsafe state, thereby avoiding deadlock (Banker's Algorithm);
3. Deadlock detection and recovery. Allow deadlocks to occur, but the operating system is responsible for detecting the occurrence of deadlock and then taking some measure to recover from it.
