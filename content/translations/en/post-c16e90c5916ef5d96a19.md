## P and V Operations

- The value of a semaphore: the **remaining quantity of this resource** (if the semaphore value is less than 0, it means some process is currently waiting for this resource);
- `P(S)`: request one resource S; if **the resource is insufficient, block and wait**;
- `V(S)`: release one resource S; if some process is waiting for this resource, **wake up one process**.


## Implementing Process Mutual Exclusion

1. Analyze the critical activities of concurrent processes and define the critical section (e.g., access to the critical resource printer should be placed in the critical section);
2. Set a **mutex semaphore** mutex, which represents **the number of slots for entering the critical section**. Its initial value is 1;
3. In the entry section, `P(mutex)` — request the resource;
4. In the exit section, `V(mutex)` — release the resource.

Note:
- **Different critical resources** require **different mutex semaphores**.
- **P and V operations must appear in pairs**. Missing `P(mutex)` means **mutually exclusive access to the critical resource cannot be guaranteed**. Missing `V(mutex)` will cause **the resource to never be released, and waiting processes to never be woken up**.

```c 
/* 信号量机制实现互斥 */
semaphore mutex = 1;

Process1 () {
    /* ... */
    P(mutex);   // 使用临界资源前加锁
    critical section; 
    V(mutex);   // 使用临界资源后解锁
    /* ... */
}

Process2 () {
    /* ... */
    P(mutex);   // 使用临界资源前加锁
    critical section; 
    V(mutex);   // 使用临界资源后解锁
    /* ... */
}

```

## Implementing Process Synchronization
Process synchronization: concurrent processes must be advanced in an orderly manner as required.

For example, P1 and P2 execute concurrently. Due to asynchrony, the order in which the two alternate and advance is uncertain.

If **"code 4" of P2 must be based on the execution results of "code 1" and "code 2" of P1** before it can execute, then we must **ensure that "code 4" is definitely executed after "code 2"**.

This is the process synchronization problem: making originally asynchronous and concurrent processes cooperate with each other and advance in an orderly manner.

Using semaphores to implement process synchronization:
1. Analyze where a "synchronization relationship" needs to be implemented, that is, the two operations (or two lines of code) that must be guaranteed to execute "one before the other";
2. Set a **synchronization semaphore S, initially 0**.
3. Execute `V(S)` **after the "preceding operation"**
4. Execute `P(S)` **before the "following operation"**

```c 
/* 信号量机制实现同步 */
semaphore mutex = 0;

Process1() {
  代码1;
  代码2;
  V(S);
  代码3;
}

Process2() {
  P(S);
  代码4;
  代码5;
  代码6;
}
```

**Analysis: semaphore S represents "some kind of resource", and initially this resource does not exist. P2 needs to use this resource, but this resource can only be produced by P1.**

If the `V(S)` operation is executed first, then after `S++`, `S=1`.
Later, when the `P(S)` operation is executed, since `S=1`, indicating that there is an available resource, `S--` will be executed, the value of S returns to 0, and process P2 will not execute the `block` primitive, but will continue to execute code 4.

If the `P(S)` operation is executed first, since `S=0`, after `S--`, `S=-1`, indicating that there is no available resource at this time, so the `block` primitive will be executed in the P operation, actively requesting to block.
Later, after code 2 is executed, the `V(S)` operation is then executed, `S++`, making S return to 0. Since there is a process in the blocking queue corresponding to this semaphore at this time, the `wakeup` primitive will be executed in the V operation to wake up process P2.
In this way, P2 can continue to execute code 4.

In fact, each pair of precedence relationships is a process synchronization problem (it is necessary to ensure that the operations occur one before the other). Therefore:
1. Set **one synchronization semaphore** for **each pair of precedence relationships**;
2. Execute a **V operation** on the corresponding synchronization semaphore **after the "preceding operation"**;
3. Execute a **P operation** on the corresponding synchronization semaphore **before the "following operation"**.
