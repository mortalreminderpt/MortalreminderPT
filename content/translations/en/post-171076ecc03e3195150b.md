## Deadlock Handling Strategies

1. Deadlock prevention. Break one or several of the four necessary conditions for deadlock;
2. Deadlock avoidance. Use some method to prevent the system from entering an unsafe state, thereby avoiding deadlock (Banker's Algorithm);
3. Deadlock detection and recovery. Allow deadlocks to occur, but the operating system is responsible for detecting the occurrence of deadlock and then taking some measure to recover from it.

## Deadlock Detection and Recovery

If the system adopts neither deadlock prevention measures nor deadlock avoidance measures, deadlock is very likely to occur.
In this case, the system should provide two algorithms:
1. Deadlock detection algorithm: used to detect the system state to determine whether a deadlock has occurred in the system.
2. Deadlock recovery algorithm: when it is determined that a deadlock has occurred in the system, this algorithm can be used to free the system from the deadlock state.

### Deadlock Detection
To be able to detect whether a deadlock has occurred in the system, it is necessary to:
1. Use **some data structure** to save resource request and allocation information;
2. Provide **an algorithm** that uses the above information to detect whether the system has entered a deadlock state.

#### Resource Allocation Graph

Two types of nodes:
- Process node: corresponds to a process;
- Resource node: corresponds to a type of resource, and a type of resource may have multiple instances.

Two types of edges:
- Process node -> Resource node: indicates that the process wants to request several resources (each edge represents one);
- Resource node -> Process node: indicates that several resources have already been allocated to the process (each edge represents one).

If the number of remaining available resources in the system is sufficient to satisfy the process's demand, then this process will not be blocked for the time being and can continue executing smoothly.

If this process finishes execution and returns its resources to the system, it may activate some processes that are waiting for resources, allowing them to continue executing smoothly.

Correspondingly, after these activated processes finish execution, they will return some resources, which may in turn activate some other blocked processes.

If analyzed according to the above process, and **all edges can ultimately be eliminated**, then the graph is said to be **completely reducible**.
At this time, **deadlock has definitely not occurred**. (This is equivalent to being able to find a **safe sequence**.)

**Deadlock Theorem**: If at some moment the system's resource allocation graph is **not completely reducible**, then the system is deadlocked at that time.

### Deadlock Recovery

Once the occurrence of deadlock is detected, the deadlock should be recovered immediately.

Note: Not all processes in the system are in a deadlock state. After **simplifying the resource allocation graph** with the deadlock detection algorithm, **the processes that still have edges connected to them are the deadlocked processes**.

The main methods for recovering from deadlock are:
1. **Resource preemption method**: Suspend (temporarily place on external storage) some deadlocked processes and preempt their resources, allocating these resources to other deadlocked processes.
However, it should be prevented that suspended processes are starved for a long time without obtaining resources.
2. **Process revocation method** (also called **process termination method**): Forcibly revoke some or even all deadlocked processes and deprive these processes of their resources.
The advantage of this method is that it is simple to implement, but the cost may be very high.
Because some processes may have been running for a long time and are already close to completion; once terminated, all previous work is wasted and they will have to start over from the beginning.
3. **Process rollback method**: Make one or more deadlocked processes roll back to a point sufficient to avoid deadlock. This requires the system to record the historical information of processes and set restore points.

### How to Decide Which Processes to Suspend, Revoke, or Roll Back

1. Process priority: processes with higher priority first;
2. How long it has been executing: processes that have run for a long time first;
3. How much longer until completion: processes with shorter remaining time first;
4. How many resources the process has already used: processes occupying more resources first;
5. Whether the process is interactive or batch: interactive processes first.
