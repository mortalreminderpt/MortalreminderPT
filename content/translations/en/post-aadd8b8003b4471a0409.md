## Concept of Semaphores

User processes can operate on **semaphores** by using a **pair of primitives** provided by the operating system, thereby conveniently achieving process mutual exclusion and process synchronization.

A **semaphore** is actually a **variable** (it can be an integer, or a more complex record-type variable), and a semaphore can be used to **represent the quantity of a certain resource in the system**.
For example: if there is only one printer in the system, a semaphore with an initial value of 1 can be set.

A **primitive** is a special **program segment** whose execution **can only be completed in one go and cannot be interrupted.**
Primitives are implemented by **disable-interrupt/enable-interrupt instructions**.
The main problem with software solutions is that "the various operations in the entry section cannot be completed in one go"; therefore, if the operations in the entry section and exit section can all be implemented with "primitives" so that these operations can be completed "in one go," the problem can be avoided.

**A pair of primitives**: the `wait(S)` primitive and the `signal(S)` primitive. The primitives can be understood as functions we write ourselves, with function names `wait` and `signal` respectively; the semaphore S in the parentheses is actually a parameter passed in when the function is called.

The `wait` and `signal` primitives are often referred to simply as **P and V operations** (from the Dutch words proberen and verhogen).

## Integer Semaphore

An **integer variable** is used as a semaphore to represent **the quantity of a certain resource in the system**.

Difference from an ordinary integer variable: there are only three operations on a semaphore, namely initialization, P operation, and V operation.

```c
int S = 1; // 初始化整型信号量S，表示当前系统中可用的打印机资源数。

void wait(int S) {      // wait原语，相当于"进入区"
    while (S <= 0);     // 如果资源数不够，就一直循环等待
    S--;                // 如果资源数够，则占用一个资源
}

void signal(int S) {    // signal原语，相当于"退出区"
    S++;                // 使用完资源后，在退出区释放资源
}
```

In an integer semaphore, "checking" and "locking" are completed in one go, avoiding problems caused by concurrency and asynchrony.

Existing problem: **it does not satisfy the "wait with relinquished CPU" principle**, and "busy waiting" will occur.

## Record-Type Semaphore

The defect of the integer semaphore is the "busy waiting" problem, so people proposed the "record-type semaphore," that is, a semaphore represented by a record-type data structure.

```c
/* 记录型信号量的定义 */
typedef struct {
    int value;          // 剩余资源数
    Struct process *L;  // 等待队列
} semaphore;

/* 某进程需要使用资源时，通过wait原语申请 */
void wait(semaphore S) {
    S.value--;
    if (S.value < 0) {
        block(S.L);
    }
}

/* 进程使用完资源后，通过signal原语释放 */
void signal(semaphore S) {
    S.value++;
    if (S.value <= 0) {
        wakeup(S.L);
    }
}
```

If the number of remaining resources is insufficient, the `block` primitive is used to make the process transition from the running state to the blocked state and hang it in the waiting queue (i.e., blocking queue) of semaphore S;
after resources are released, if there are still other processes waiting for this resource, the `wakeup` primitive wakes up one process in the waiting queue, and that process changes from the blocked state to the ready state.

`wait(S)` and `signal(S)` can also be denoted as `P(S)` and `V(S)`; this pair of primitives can be used to **implement the "request" and "release" of system resources**.

The initial value of `S.value` represents **the number of a certain resource** in the system.

**One P operation** on semaphore S means the process **requests one unit of that type of resource**, so `S.value--` needs to be executed, indicating that the number of resources is decreased by 1;
when `S.value < 0`, it indicates that this type of resource has been fully allocated, so the process should call the `block` primitive to **block itself** (the currently running process goes from **running state -> blocked state**), voluntarily give up the processor, and insert itself into the waiting queue `S.L` of this type of resource.
It can be seen that this mechanism **follows the "wait with relinquished CPU" principle** and will not exhibit "busy waiting."

**One V operation** on semaphore S means the process **releases one unit of that type of resource**, so `S.value++` needs to be executed, indicating that the number of resources is increased by 1;
if after the increase by 1 it is still `S.value <= 0`, it indicates that there are still processes waiting for this type of resource, so the `wakeup` primitive should be called to **wake up the first process in the waiting queue** (the awakened process goes from **blocked state -> ready state**).
