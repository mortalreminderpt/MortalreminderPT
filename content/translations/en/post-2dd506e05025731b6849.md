## Interrupt Masking Method
Implemented using "enable/disable interrupt instructions".
The idea is the same as the implementation of primitives: from the moment a process starts accessing the critical section until it finishes, interrupts are not allowed, so process switching cannot occur, and therefore it is impossible for two processes to access the critical section at the same time.

```
...
关中断指令;
临界区;
开中断指令;
...
```

- **Disable interrupt instruction**: after interrupts are disabled, the current process is not allowed to be interrupted, and process switching will necessarily not occur; 
- **Enable interrupt instruction**: only after the current process has finished accessing the critical section and then executes the enable interrupt instruction is it possible for another process to get on the processor and access the critical section.

- Advantages: simple and efficient
- Disadvantages: **not applicable to multiprocessors**; only applicable to operating system kernel processes, **not applicable to user processes** (because the enable/disable interrupt instructions can only run in kernel mode, and it would be very dangerous if these instructions could be used freely by users).




## TestAndSet Instruction (TS/TSL Instruction)
The TS instruction is implemented in hardware, and **its execution process is not allowed to be interrupted**; it must be completed in one go. The following is the logic described in C language:

```c
/* 布尔型共享变量lock表示当前临界区是否被加锁
 * true表示已加锁,false表示未加锁 
 */
bool testAndSet (bool *lock) {
    bool old; 
    old = *lock; // old 用来存放lock原来的值
    *lock = true; // 无论是否已加锁，都设置为true
    return old; // 返回lock原来的值
}

/* 使用TSL指令实现互斥的算法逻辑 */
while (testAndSet(&lock)); // 上锁并检查
critical section; // 临界区代码
lock = false; // 解锁操作
remainder section; // 剩余区代码
```

If lock is initially false, the old value returned by TS is false, the while loop condition is not satisfied, the loop is skipped directly, and the process enters the critical section;
If lock is initially true, then after executing TS the returned old value is true, the while loop condition is satisfied, and it will keep looping until the process currently accessing the critical section performs "unlock" in the exit section.
Compared with software implementation methods, the TS instruction turns the **"locking" and "checking"** operations **into an atomic operation completed in one go by hardware means**.

- Advantages: simple to implement, no need to strictly check for logical loopholes as with software implementation methods; **applicable to multiprocessor** environments;
- Disadvantages: **does not satisfy the "wait by yielding the right" principle**; a process temporarily unable to enter the critical section will occupy the CPU and repeatedly execute the TSL instruction, resulting in "busy waiting".


## Swap Instruction (Exchange/XCHG Instruction)
The Swap instruction is implemented in hardware, and its execution process is not allowed to be interrupted; it must be completed in one go. The following is the logic described in C language:

```c
/* Swap指令是交换两个变量的值 */
swap (bool *a, bool *b) {
    bool temp;
    temp = *a;
    *a = *b;
    *b = temp;
}

/* 使用Swap指令实现互斥的算法逻辑 */
bool old = true;
while (old == true)
    swap (&lock, *old);
critical section; // 临界区代码
lock = false; // 解锁操作
remainder section; // 剩余区代码
```

Logically, Swap and TS are not very different: both first record whether the critical section is currently locked (recorded in the old variable), then set the lock flag lock to true, and finally check old.
If old is false, it means no other process had locked the critical section before, so the loop can be exited and the process can enter the critical section.

- Advantages: simple to implement, no need to strictly check for logical loopholes as with software implementation methods; **applicable to multiprocessor** environments;
- Disadvantages: **does not satisfy the "wait by yielding the right" principle**; a process temporarily unable to enter the critical section will occupy the CPU and repeatedly execute the Swap instruction, resulting in "busy waiting".
