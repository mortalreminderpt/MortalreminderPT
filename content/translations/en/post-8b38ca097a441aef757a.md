## Understanding the difference between a "process" and a "program"

Program: it is **static**; it is just an executable file stored on a disk, that is, a series of instructions.

Process: it is **dynamic**; it is a single execution of a program (the same program executed multiple times corresponds to multiple processes).

## What parts make up a process entity

### Process Control Block (PCB)

When a process is created, the operating system assigns it a **unique, non-repeating** "ID number" — the Process ID (**PID**).

The operating system must record basic process description information such as the PID and the ID of the user the process belongs to (UID), so that the operating system can distinguish between processes.

It must also record which resources have been allocated to the process (such as how much memory has been allocated, which I/O devices are in use, and which files are in use), to enable the operating system to manage resources.

It must also record the process's running status (such as CPU usage time, disk usage, and network traffic usage), to enable the operating system to control and schedule the process.

All of this information is stored in a data structure called the **PCB (Process Control Block)**, that is, the **process control block**. The PCB is the only sign that a process exists; when a process is created, the operating system creates a PCB for it, and when the process ends, its PCB is reclaimed.

The operating system needs to manage the various concurrently running processes, and **any information needed for management is placed in the PCB.**

A **process entity (process image)** consists of the **PCB, program segment, and data segment**. A **process** is **dynamic**, while a **process entity (process image)** is **static**, similar to a snapshot of the process.

The process entity reflects the state of the process at a certain moment (for example, after x++, x=2).

- The PCB is for the operating system to use;
- The program segment and data segment are for the process itself to use and are related to the process's own execution logic.

The three parts — **program segment, data segment, and PCB** — together make up the **process entity (process image)**.

After introducing the concept of the process entity, a process can be defined as:
A **process** is the **execution process** of a process entity, and is an independent unit for the system to perform **resource allocation and scheduling**.

Note: the PCB is the only sign that a process exists.

## What important characteristics do processes have

A program is static, while a process is dynamic. Compared with a program, a process has the following characteristics:

1. **Dynamism**: a process is a single execution of a program, dynamically arising, changing, and dying out;
2. Concurrency: there are multiple process entities in memory, and each process can execute concurrently;
3. Independence: a process is the basic unit that can run independently, obtain resources independently, and accept scheduling independently;
4. Asynchrony: each process advances at its own independent and unpredictable speed, and the operating system must provide a "process synchronization mechanism" to solve the asynchrony problem;
5. Structure: every process is configured with a PCB. Structurally, a process consists of a program segment, a data segment, and a PCB.

Among these, **dynamism is the most basic characteristic of a process**, and asynchrony leads to uncertainty in the execution results of concurrent programs.
