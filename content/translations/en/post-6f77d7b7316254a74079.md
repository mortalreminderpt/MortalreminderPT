## Timing

**Process scheduling (low-level scheduling)** is the process of selecting a process from the ready queue according to some algorithm and allocating a processor to it.

### Situations where process scheduling and switching are required

The situations where process scheduling and switching **are required** fall mainly into two categories: **voluntary relinquishment** and **involuntary relinquishment**.

The currently running process **voluntarily relinquishes** the processor:
- The process terminates normally;
- The process terminates due to an exception during execution;
- The process voluntarily requests to block (e.g., waiting for I/O).

The currently running process **involuntarily relinquishes** the processor:
- The time slice allocated to the process is used up;
- A more urgent matter needs to be handled (e.g., an I/O interrupt);
- A process with higher priority enters the ready queue.

### Situations where process scheduling and switching cannot be performed

Situations where process scheduling and switching **cannot be performed**:
- **During interrupt handling**. Interrupt handling is complex and closely tied to hardware, making it very difficult to perform process switching during interrupt handling;
- The process is in a **critical section of an operating system kernel program**;
- During an atomic operation (primitive). Atomic operations cannot be interrupted and must be completed in one go (e.g., modifying the process state flag in the PCB and placing the PCB into the corresponding queue).

### Scheduling and switching cannot be performed in a critical section of an operating system kernel program

Critical resource: a resource that only one process is allowed to use within a given time period. Processes need to access critical resources **mutually exclusively**.

Critical section: the code that accesses a critical resource.

A **kernel program critical section** is generally used to access some kind of **kernel data structure**, such as the process ready queue (composed of the PCBs of the ready processes).

If the critical resource accessed by a kernel program critical section is not released as soon as possible, it is very likely to affect other management work of the operating system kernel. Therefore, scheduling and switching cannot be performed while accessing a kernel program critical section.

## Modes

In some systems, processes are only allowed to voluntarily relinquish the processor;

while in other systems, processes can voluntarily relinquish the processor, and when a more urgent task needs to be handled, the processor is forcibly preempted.

Therefore, the modes of process scheduling can be divided into **non-preemptive scheduling** and **preemptive scheduling**.

### Non-preemptive scheduling mode (non-preemptive)

**Non-preemptive scheduling mode, also called non-preemptive mode**. That is, processes are only allowed to voluntarily relinquish the processor. During execution, even if a more urgent task arrives, the current process will continue to use the processor until it terminates or voluntarily requests to enter the blocked state.

Non-preemptive scheduling is simple to implement and has low system overhead, but it cannot handle urgent tasks in a timely manner. It is suitable for early batch processing systems.

### Preemptive scheduling mode (preemptive)

**Preemptive scheduling mode, also called preemptive mode**. When a process is executing on the processor, if a more important or more urgent process needs to use the processor, the executing process is immediately suspended and the processor is allocated to the more important and urgent process.

Preemptive scheduling can prioritize more urgent processes and can also implement the function of letting processes execute in turn according to time slices (through clock interrupts). It is suitable for time-sharing operating systems and real-time operating systems.

## Switching and Process

Process scheduling and process switching in the narrow sense:

**Process scheduling in the narrow sense** refers to **selecting a process to run** from the ready queue.
(This process may be the process that was just suspended, or it may be **another process**; the latter case requires **process switching**.)

**Process switching** refers to the process in which one process gives up the processor and another process occupies the processor.

**Process scheduling in the broad sense** includes two steps: selecting a process and process switching.

The process switching procedure mainly accomplishes:

1. Saving various data of the original running process;
2. Restoring various data of the new process. (Such as the program counter, program status word, various data registers, and other processor on-site information; this information is generally saved in the process control block.)

Note: **Process switching has a cost**, so if process **scheduling and switching** are performed **too frequently**, the **efficiency of the entire system** will inevitably **decrease**, causing the system to spend most of its time on process switching and reducing the time actually used to execute processes.
