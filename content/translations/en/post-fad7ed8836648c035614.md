## Problem Description
There is a plate on the table, and only one fruit can be placed into it at a time.
The father only puts apples into the plate, the mother only puts oranges into the plate, the son only waits to eat the oranges in the plate, and the daughter only waits to eat the apples in the plate.
Only when the plate is empty can the father or mother put a fruit into the plate.
Only when the plate contains the fruit they need can the son or daughter take the fruit out of the plate.

## Implementation Principles

Mutual exclusion relationship (mutex = 1):
- Access to the buffer (plate) must be performed mutually exclusively.

Synchronization relationships (one before the other):
1. Only after the father puts an apple into the plate can the daughter take the apple;
2. Only after the mother puts an orange into the plate can the son take the orange;
3. Only when the plate is empty can the father or mother put a fruit in. (The event "the plate is empty" can be triggered by either the son or the daughter, and only after this event occurs is the father or mother allowed to put a fruit in.)

## Code Implementation

```c
semaphore mutex = 1;   //实现互斥访问盘子（缓冲区）
semaphore apple = 0;   //盘子中有几个苹果
semaphore orange = 0;  //盘子中有几个橘子
semaphore plate = 1;   //盘子中还可以放多少个水果

dad() {
    while(1) {
        准备一个苹果;
        P(plate);
        P(mutex);
        把苹果放入盘子;
        V(mutex);
        V(apple);
    }
}

mom() {
    while(1) {
        准备一个橘子；
        P(plate);
        P(mutex);
        把橘子放入盘子;
        V(mutex);
        V(orange);
    }
}

daughter() {
    while(1) {
        P(apple);
        P(mutex);
        从盘中取出苹果;
        V(mutex);
        V(plate);
        吃掉苹果;
    }
}

son() {
    while(1) {
        P(orange);
        P(mutex);
        从盘中取出橘子;
        V(mutex);
        V(plate);
        吃掉橘子;
    }
}
```

## The Case of Removing the Mutex Semaphore

### Buffer capacity is 1

When the buffer capacity is 1, even if no dedicated mutex variable mutex is set, the phenomenon of multiple processes accessing the plate at the same time will not occur.

Analysis: At the beginning, even if the son and daughter processes are scheduled onto the processor, they will be blocked.
If the father process is the first to be scheduled onto the processor at the beginning, then the father `P(plate)`, and can access the plate ->
the mother `P(plate)`, and blocks waiting for the plate ->
the father puts an apple in `V(apple)`, the daughter process is woken up, and even if other processes run they will all be blocked, so it is temporarily impossible to access the critical resource (the plate) ->
the daughter `P(apple)`, accesses the plate, `V(plate)`, and the mother process waiting for the plate is woken up ->
the mother process accesses the plate (other processes are temporarily unable to enter the critical section) -> ...

The reason is that the buffer size in this problem is 1.
At any moment, among the three synchronization semaphores apple, orange, and plate, at most only one is 1.
Therefore, at most only one process's P operation will not be blocked and can smoothly enter the critical section.

### Buffer capacity is 2

The father `P(plate)`, and can access the plate ->
the mother `P(plate)`, and can access the plate ->
the father is putting an apple into the plate, and at the same time the mother can also put an orange into the plate.
Thus the situation arises where two processes access the buffer at the same time, which may cause the data written to the buffer by the two processes to overwrite each other.
Therefore, if the buffer size is greater than 1, a dedicated mutex semaphore mutex must be set to ensure mutually exclusive access to the buffer.

## Summary

The key to solving the "multi-producer-multi-consumer problem" lies in clarifying the complex synchronization relationships.

When analyzing synchronization problems (one-before-the-other problems), one must not analyze from the perspective of the behavior of a single process; instead, the things that happen "one before the other" should be regarded as the before-and-after relationship between two "events".

For example, if we consider it from the perspective of the behavior of a single process, we would reach the following conclusions:
- **If the plate contains an apple, then only after the daughter takes the apple away can the father or mother put another fruit in;**
- **If the plate contains an orange, then only after the son takes the orange away can the father or mother put another fruit in.**

Does looking at it this way mean that four synchronization semaphores must be set to implement these four "one-before-the-other" relationships respectively?

The correct analysis method should **consider it from the perspective of "events"**. We can abstract the above **four pairs of "before-and-after relationships of process behaviors"** into **one pair of "before-and-after relationships of events"**
Plate becomes empty event -> put fruit event:
- **The "plate becomes empty event" can be triggered by either the son or the daughter;**
- **The "put fruit event" may be executed by either the father or the mother.**

In this way, one synchronization semaphore can solve the problem.
