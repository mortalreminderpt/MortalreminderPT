1. Table of Contents
{:toc}

### **State**
**Type signature:** `type State = any`

**Explanation:**
State represents the overall data structure of the application and is managed by the Redux store. It is usually a deeply nested object that holds all the state information of the application. Ensure that State is serializable to facilitate debugging and persistence.

### **Action**
**Type signature:** `type Action = Object`

**Explanation:**
Action is a plain object that describes "what happened" and must contain a `type` field to identify the specific operation type. Action is the only way to change State; it is sent to the store via `dispatch`.

### **Reducer**
**Type signature:** `type Reducer<S, A> = (state: S, action: A) => S`

**Explanation:**
Reducer is a pure function that receives the current State and an Action and returns a new State. It decides how to update State based on the Action type, ensuring the immutability of State.

### **Dispatch Function**
**Type signature:**
```flow
type BaseDispatch = (a: Action) => Action
type Dispatch = (a: Action | AsyncAction) => any
```

**Explanation:**
`dispatch` is the function used to send Actions. The basic `dispatch` can only handle synchronous plain Actions, while Middleware can extend `dispatch` to handle asynchronous Actions.

### **Action Creator**
**Type signature:** `type ActionCreator<A, P extends any[] = any[]> = (...args: P) => Action | AsyncAction`

**Explanation:**
Action Creator is a function used to create Action objects. It encapsulates the Action creation logic and ensures consistency of the Action structure, and is usually used together with `dispatch`.

### **Async Action**
**Type signature:** `type AsyncAction = any`

**Explanation:**
An asynchronous Action is an Action that needs to be processed by Middleware, and is usually used to handle asynchronous operations such as API requests. Middleware converts an asynchronous Action into one or more plain Actions so that the Reducer can process them.

### **Middleware**
**Type signature:**
```flow
type MiddlewareAPI = { dispatch: Dispatch, getState: () => State }
type Middleware = (api: MiddlewareAPI) => (next: Dispatch) => Dispatch
```

**Explanation:**
Middleware is a tool that extends the functionality of `dispatch`, allowing interception, modification, or execution of side effects before an Action is sent to the Reducer. It is commonly used to handle asynchronous operations, logging, and so on.

### **Store**
**Type signature:**
```flow
type Store = {
  dispatch: Dispatch
  getState: () => State
  subscribe: (listener: () => void) => () => void
  replaceReducer: (reducer: Reducer) => void
}
```

**Explanation:**
Store is the container that holds the application State and provides methods such as `dispatch`, `getState`, `subscribe`, and `replaceReducer`, which are used to manage and access State and to respond to changes in State.

### **Store Creator**
**Type signature:** `type StoreCreator = (reducer: Reducer, preloadedState: ?State) => Store`

**Explanation:**
Store Creator is a function used to create a Redux Store. It receives a Reducer and an initial State and returns a configured Store instance.

### **Store Enhancer**
**Type signature:** `type StoreEnhancer = (next: StoreCreator) => StoreCreator`

**Explanation:**
Store Enhancer is a higher-order function used to enhance the Store creation process. It can extend the functionality of the Store, such as adding Middleware support and enhancing debugging capabilities. A common example is `applyMiddleware`.
