## Introduction

This chapter introduces three scheduling algorithms suitable for **interactive systems**.

|Algorithm|Preemptive|Advantages|Disadvantages|Causes starvation|
|--|--|--|--|
|RR|Preemptive|Fair, suitable for time-sharing systems|Frequent switching incurs overhead; does not distinguish priorities|No|
|PSA|Both preemptive and non-preemptive|Distinguishes priorities, suitable for real-time systems|May cause starvation|Yes|
|MLFQ|Preemptive|Balanced, excellent|May cause starvation|Yes|

Compared with early batch processing operating systems, since the cost of computers has dropped significantly, the interactive operating systems that appeared later (including time-sharing operating systems, real-time operating systems, etc.) pay more attention to metrics such as system response time, fairness, and balance.
These algorithms happen to satisfy the needs of interactive systems well. Therefore, **these three algorithms are suitable for interactive systems**. (For example, UNIX uses the multi-level feedback queue scheduling algorithm.)

## RR Algorithm

### Characteristics of the RR Algorithm

|Algorithm name|Round-Robin (RR)|
|--|--|
|Algorithm idea|Serve each process fairly and in turn, so that every process can get a response within a certain time interval|
|Algorithm rule|According to the order in which processes arrive at the ready queue, let each process execute in turn for one **time slice** (e.g., 100ms). If a process does not finish within one time slice, the processor is taken away, and the process is placed back at the tail of the ready queue to wait again.|
|Used for job/process scheduling|Used for process scheduling (only after a job is loaded into memory and a corresponding process is created can it be allocated a processor time slice)|
|Preemptive or not|If a process cannot finish running within its time slice, its right to use the processor is forcibly taken away, so the round-robin scheduling algorithm is a **preemptive** algorithm. The clock device issues a **clock interrupt** to notify the CPU that the time slice has expired|
|Advantages and disadvantages|Advantages: fair, fast response, suitable for time-sharing operating systems; <br />Disadvantages: due to high-frequency process switching, there is some overhead; does not distinguish the urgency of tasks.|
|Causes starvation or not|No|

At this time P2 is at the head of the queue, so P2 is put on the processor. (Note: at time 2, P1 leaves the processor, and at the same moment the new process P2 arrives; **by default, newly arrived processes enter the ready queue first**)|
|4|**P1(3)**->P3(1)->P2(2)|P3 arrives and is first inserted at the tail of the ready queue; immediately afterward, P2 leaves the processor and is also inserted at the tail of the queue|

|14|-|The ready queue is empty, so P4 continues to run for one more time slice|

## PSA Algorithm

### Characteristics of the PSA Algorithm

|Algorithm name|Priority Scheduling Algorithm (PSA)|
|--|--|
|Algorithm idea|With the development of computers, especially the emergence of real-time operating systems, more and more application scenarios need to determine the processing order according to the urgency of tasks|
|Algorithm rule|Each job/process has its own priority, and scheduling selects the job/process with the highest priority|
|Used for job/process scheduling|It can be used for both job scheduling and process scheduling. It may even be used in later I/O scheduling|
|Preemptive or not|Both preemptive and non-preemptive versions exist. The non-preemptive version only needs to schedule when a process voluntarily gives up the processor, while the preemptive version also needs to check whether preemption will occur when the ready queue changes.|
|Advantages and disadvantages|Advantages: uses priority to distinguish urgency and importance, suitable for real-time operating systems. Can flexibly adjust the degree of preference for various jobs/processes. <br />Disadvantages: if high-priority processes keep arriving continuously, starvation may occur|
|Causes starvation or not|Yes|

### Preemptive PSA
Preemptive priority scheduling algorithm: each time scheduling occurs, select the process that has **currently arrived and has the highest priority**. Scheduling occurs when the current process **voluntarily gives up the processor**.
In addition, when the **ready queue changes**, it is also necessary to check whether preemption will occur.

|Time|Ready queue|Analysis|
|--|--|--|
|0|**P1**|Only P1 has arrived, so P1 is put on the processor|
|2|P1, **P2**|P2 arrives in the ready queue with a higher priority than P1, so preemption occurs. P1 returns to the ready queue, and P2 is put on the processor.|
|4|P1, P2, **P3**|P3 arrives with a higher priority than P2, so P2 returns to the ready queue and P3 preempts the processor|
|5|P1, **P2**, P4|P3 finishes and voluntarily releases the processor; at the same time, P4 also arrives. Since P2 entered the ready queue earlier than P4, P2 is selected to be put on the processor|
|7|P1, **P4**|P2 finishes; only P1 and P4 remain in the ready queue, so P4 is put on the processor.|
|11|**P1**|P4 finishes, so P1 is put on the processor|
|16|-|P1 finishes; all processes have ended|

### Supplement

There may not necessarily be only one ready queue; they can be organized according to different priorities. In addition, processes with higher priorities can also be placed closer to the head of the queue;

According to whether the priority can be changed dynamically, priorities can be divided into **static priority** and **dynamic priority**:
- Static priority: determined when the process is created and remains unchanged afterward;
- Dynamic priority: has an initial value when the process is created, and afterward the priority is dynamically adjusted according to circumstances.

Usually:
- System processes have **higher** priority than user processes;
- Foreground processes have **higher** priority than background processes;
- The operating system prefers I/O-bound processes (also called I/O-intensive processes; I/O devices and the CPU can work **in parallel**. If I/O-intensive processes are allowed to run first, it is more likely that I/O devices can start working as early as possible, so resource utilization and system throughput will both improve.)

The opposite of I/O-bound processes are compute-bound processes (also called CPU-intensive processes)

Dynamic priority adjustment can be considered from the perspectives of pursuing fairness and improving resource utilization:
- If a process has waited in the ready queue for a long time, its priority can be appropriately raised;
- If a process has occupied the processor and run for a long time, its priority can be appropriately lowered; 
- If a process is found to perform I/O operations frequently, its priority can be appropriately raised.

## MLFQ Algorithm

### Characteristics of the MLFQ Algorithm

|Algorithm name|Multi-Level Feedback Queue (MLFQ)|
|--|--|
|Algorithm idea|A compromise among other scheduling algorithms|
|Algorithm rule|1. Set up multiple ready queues; for each level, **priority goes from high to low, and time slice goes from small to large**<br />2. When a new process arrives, it first enters level 1 queue and waits in line according to the **FCFS principle** to be allocated a time slice. If **the process has not finished after using up its time slice, it enters the tail of the next-level queue**. If it is already in the lowest-level queue, it is placed back at the tail of that queue<br />3. Only **when the level-k queue is empty will a time slice be allocated to the process at the head of the level-(k+1) queue**|
|Used for job/process scheduling|Used for process scheduling|
|Preemptive or not|A **preemptive** algorithm. During the execution of a process in the level-k queue, if a new process enters a higher-level queue (levels 1 to k-1), then because the new process is in a queue with higher priority, the new process will preempt the processor, and the originally running process is placed back at the tail of the level-k queue.|
|Advantages and disadvantages|Relatively fair to various types of processes (advantage of FCFS); each newly arrived process can get a response quickly (advantage of RR); short processes can be completed with less time (advantage of SPF); there is no need to estimate process running time (avoiding user cheating); the degree of preference for various types of processes can be flexibly adjusted, such as CPU-intensive processes and I/O-intensive processes (processes blocked due to I/O can be placed back into the original queue, so I/O-bound processes can maintain a higher priority)|
|Causes starvation or not|Yes|

### Example
The arrival times at the ready queue and the required running times of each process are shown in the table below. Use the multi-level feedback queue scheduling algorithm to analyze the process execution.

|Process|Arrival time|Running time|
|--|--|--|
|P1|0|8|
|P2|1|4|
|P3|5|1|

Set up multiple ready queues; for each level, **priority goes from high to low, and time slice goes from small to large;**

**When a new process arrives, it first enters the level 1 queue** and waits in line according to the **FCFS principle** to be allocated a time slice. If the process has not finished after using up its time slice, it enters the tail of the next-level queue.
If it is already in the lowest-level queue, it is placed back at the tail of the lowest-level queue;

Only **when the level-k queue is empty** will **a time slice be allocated to the process at the head of the level-(k+1) queue**;

**A process whose processor is preempted** is placed back at **the tail of its original queue**.

Assume that the multi-level feedback queue at this time has 3 levels in total; the priorities of the 3 levels go from high to low, and the time slices are 1, 2, and 4 respectively.

|Time|Level 1 queue (time slice 1)|Level 2 queue (time slice 2)|Level 3 queue (time slice 4)|Analysis|
|--|--|--|--|--|
|0|**P1(8)**|-|-|Only P1 has arrived, so it is put on the processor|
|1|**P2(4)**|P1(7)|-|P1 **has used up its time slice but the task is not finished, so it is placed in the level 2 queue**; at the same time, P2 arrives in the level 1 queue and is put on the processor first to run|
|2|-|**P1(7)**->P2(3)|-|P2 has used up its time slice but the task is not finished, so it is placed in the level 2 queue; at this time the level 1 queue is empty, so P1 at the head of the level 2 queue is put on the processor to run|
|4|-|**P2(3)**|P1(5)|P1 has used up its time slice but the task is not finished, so it is placed in the level 3 queue; at this time the level 1 queue is empty, so P2 is put on the processor to run|
|5|**P3(1)**|P2(2)|P1(5)|P3 arrives and is in a higher-priority queue, so it **preempts the processor**; P2 leaves the processor and is **placed back at the tail of its original queue**|
|6|-|**P2(2)**|P1(5)|P3 finishes running, so P2 in the level 2 queue is put on the processor|
|8|-|-|**P1(5)**|P2 finishes running, so P1 in the level 3 queue is put on the processor|
|12|-|-|**P1(1)**|P1 has used up its time slice; the level 3 queue is already the **lowest level, so it is placed back**, and since only P1 remains in the queue, it is put on the processor|
|13|-|-|-|All programs have finished running|

Between queues, fixed priority or **time slice division** can be adopted:
- Fixed priority: lower-priority processes can be scheduled only when higher-priority queues are empty;
- Time slice division: for example, three queues are allocated 50%, 40%, and 10% of the time

Each queue can adopt a different scheduling strategy, such as:
- System process queue uses PSA
- Interactive queue uses RR
- Batch processing queue uses FCFS
