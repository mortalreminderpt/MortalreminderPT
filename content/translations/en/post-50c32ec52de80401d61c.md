## How Programs Run
After the code is written, the compiler "translates" the high-level language into binary machine instructions. **The process of a program running is actually the process of the CPU executing machine instructions one by one**.

An "instruction" is the most basic command that the processor (CPU) can recognize and execute.

Many people are used to also calling the commands used in the "little black box" of Linux, Windows, and MacOS "instructions". In fact, this is an "interactive command interface"; note the difference from the "instructions" in this section. The "instructions" in this section refer to binary machine instructions.

## Kernel Programs and Application Programs
Programs written by ordinary programmers are "**application programs**";

Microsoft and Apple have teams responsible for implementing operating systems. What they write are "**kernel programs**". Many kernel programs together form the "**operating system kernel**", or "**kernel**" for short. The kernel is the most important and core part of the operating system, and also the **part closest to the hardware**.

An operating system only needs a kernel to be sufficient (for example, Docker only needs the Linux kernel). The functions of an operating system are not necessarily all in the kernel, such as the GUI.

## Privileged Instructions and Unprivileged Instructions
As the "manager", the operating system kernel sometimes makes the CPU execute some "privileged instructions", such as the memory clear instruction. These instructions have major impact and are only allowed to be used by the "manager", that is, the operating system kernel.

Application programs can only use "unprivileged instructions", such as addition instructions, subtraction instructions, and so on.

**Privileged instructions and unprivileged instructions are divided at the time of CPU design and production**, so the CPU can determine the type of an instruction before executing it.

## Kernel Mode and User Mode of the Processor
Although the CPU can determine the instruction type, how does it distinguish whether a kernel program or an application program is currently running?

The CPU has two states: "**kernel mode**" and "**user mode**"

When in kernel mode, it means that **a kernel program is currently running**, and **privileged instructions can be executed** at this time;

When in user mode, it means that **an application program is currently running**, and **only unprivileged instructions can be executed** at this time.

    CPU中有一个寄存器叫程序状态字寄存器（PSW），其中有个二进制位，1表示“内核态”，0表示“用户态”。

### Conversion Between Kernel Mode and User Mode

1. Just after booting, the CPU is in "kernel mode", and the operating system kernel program first runs on the CPU;
2. After booting is complete, the user can start an application program;
3. The operating system kernel program voluntarily gives up the CPU at an appropriate time, allowing the application program to run on the CPU (before giving up the CPU, the operating system kernel will **use a privileged instruction to set the PSW flag bit to "user mode"**);
4. The application program runs in "user mode";
5. A privileged instruction is embedded in the application program. The CPU finds that the next instruction to be executed is a privileged instruction, but it is itself in "user mode";
6. Therefore, this event will trigger an **interrupt signal** (**after the CPU detects the interrupt signal**, it will immediately **switch to "kernel mode"**, stop running the current application program, and instead run the kernel program that handles the interrupt signal);
7. The "interrupt" causes the operating system to regain control of the CPU;
8. The operating system will handle the event that caused the interrupt, and after handling it, hand over CPU usage to another application program.

Kernel mode → user mode: execute a **privileged instruction—modify the PSW** flag bit to "user mode". This action means that the operating system will voluntarily give up CPU usage.

User mode → kernel mode: triggered by an "**interrupt**". **The hardware automatically completes the mode-switching process**. Triggering an interrupt signal means that the operating system will forcibly take back CPU usage (in addition to illegal use of privileged instructions, many other events will also trigger interrupt signals. One commonality is that **wherever operating system intervention is needed, an interrupt signal will be triggered**).
