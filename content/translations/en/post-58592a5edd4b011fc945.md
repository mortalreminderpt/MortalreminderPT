## Purpose

`useContext` is a Hook provided by React for subscribing to React Context within function components. It allows us to conveniently access data provided by upper-level components through Context in deeply nested components within the component tree, without needing to manually pass it through props at each level.

**Example:**

```jsx
import React, { useContext } from 'react';

const ThemeContext = React.createContext('light');

function ThemedButton() {
  const theme = useContext(ThemeContext);
  return <button className={theme}>按钮</button>;
}
```

In this example, the `ThemedButton` component uses `useContext` to obtain the current theme from `ThemeContext` and applies it to the button's style.

## Notes

### 1. Must be used together with Context.Provider

The value obtained by `useContext` comes from the `value` provided by the nearest upper-level `<Context.Provider>` to the current component in the component tree. If there is no corresponding Provider in the component tree, `useContext` will return the default value provided when `createContext` was called.

**Example:**

```jsx
const ThemeContext = React.createContext('light'); // 默认值为 'light'

function App() {
  return (
    <ThemeContext.Provider value="dark">
      <Toolbar />
    </ThemeContext.Provider>
  );
}
```

### 2. `useContext` subscribes to changes in the context

When the `value` of the Context changes, components using `useContext` will re-render. `useContext` uses `Object.is` to compare the old and new values.

### 3. `useContext` cannot create a new Context inside a component

If a new Context is created or provided inside the component that calls `useContext`, `useContext` will not be able to obtain the expected value. `useContext` can only subscribe to Providers that are higher than the current component in the component tree.

**Incorrect example:**

```jsx
function MyComponent() {
  const MyContext = React.createContext(); // ❌ 不要在组件内部创建 Context
  const value = useContext(MyContext);
  // ...
}
```

### 4. Avoid performance issues caused by multiple renders

If the `value` passed through Context is a new object or function, components using `useContext` will re-render every time the Provider updates. To avoid unnecessary re-renders, you can optimize using `useMemo` or `useCallback`.

**Example:**

```jsx
function App() {
  const [user, setUser] = useState(null);

  const contextValue = useMemo(() => ({ user, setUser }), [user]);

  return (
    <UserContext.Provider value={contextValue}>
      <MyComponent />
    </UserContext.Provider>
  );
}
```

### 5. Using multiple Contexts

In complex applications, multiple Contexts may be needed. Each Context needs a corresponding Provider, and `useContext` must be called separately when using them.

**Example:**

```jsx
const ThemeContext = React.createContext('light');
const AuthContext = React.createContext(null);

function MyComponent() {
  const theme = useContext(ThemeContext);
  const auth = useContext(AuthContext);
  // ...
}
```

## What you can do

- **Pass data across the component tree**: Context can be used to pass data deeply through the component tree, avoiding the hassle of passing props level by level.

  **Example:**

  ```jsx
  // 在顶层组件提供 Context
  <ThemeContext.Provider value="dark">
    <App />
  </ThemeContext.Provider>
  ```

- **Subscribe to changes in Context**: When the `value` of the Context changes, components using `useContext` will automatically re-render.

- **Combine with `useState` or `useReducer`**: State and update functions can be passed through Context to achieve the effect of global state management.

  **Example:**

  {% raw %}
  ```jsx
  const AuthContext = React.createContext();

  function App() {
    const [auth, setAuth] = useState(null);

    return (
      <AuthContext.Provider value={{ auth, setAuth }}>
        <MyComponent />
      </AuthContext.Provider>
    );
  }
  ```
  {% endraw %}

## What you should not do

- **Do not create Context inside a component**: Context should be created outside the component; otherwise, a new Context will be created on every render, preventing child components from subscribing correctly.

  **Incorrect example:**

  ```jsx
  function MyComponent() {
    const MyContext = React.createContext(); // ❌ 不要在组件内部创建 Context
    const value = useContext(MyContext);
    // ...
  }
  ```

- **Do not overuse Context**: Context is suitable for global data passing that spans multiple component layers. If data is only passed between parent and child components, using props is more appropriate.

- **Avoid passing frequently changing values**: If the `value` of the Context changes frequently, components using `useContext` will re-render frequently, which may affect performance. Try to avoid passing frequently changing data through Context.

- **Do not use `useContext` in loops or conditions**: `useContext` must be called at the top level of a component and cannot be called in loops, conditions, or nested functions.

  **Incorrect example:**

  ```jsx
  function MyComponent() {
    if (condition) {
      const value = useContext(MyContext); // ❌ 不要在条件语句中使用
    }
    // ...
  }
  ```

## Summary

`useContext` is the Hook in React used to subscribe to Context. It allows us to conveniently share data across the component tree and avoids manually passing props level by level. However, when using `useContext`, pay attention to the following points:

- **Use Provider correctly**: Ensure that the corresponding `value` is provided through `<Context.Provider>` in the component tree, and that the Provider is located above the component that uses `useContext`.

- **Avoid performance issues**: For Context that passes objects or functions, use `useMemo` or `useCallback` to optimize and avoid unnecessary re-renders.

- **Use Context appropriately**: Context is suitable for global data passing that spans multiple component layers. For local state, component state or props should still be used.

- **Follow the Hooks rules**: `useContext` must be called at the top level of a component and cannot be called in loops, conditions, or nested functions.

By using `useContext` appropriately, we can manage and share data more efficiently in React applications, improving code maintainability and readability.
