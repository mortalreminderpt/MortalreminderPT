## The Role of `useRef`

`useRef` is a Hook provided by React that lets us create a mutable ref object whose `.current` property can hold any mutable value. Its most common use is accessing DOM elements, but it can also be used to store any mutable value that needs to remain unchanged between renders without triggering a re-render.

**Example:**

{% raw %}
```jsx
import { useRef } from 'react';

function MyComponent() {
  const inputRef = useRef(null);
  // ...
}
```

In this example, we create a `inputRef` with an initial value of `null`, which we can later associate with a DOM element or use to store other data.

## Precautions When Using `useRef`

### 1. The object returned by `useRef` remains unchanged throughout the component's lifecycle

When you call `useRef`, it returns an object containing a `current` property. This object remains unchanged throughout the component's entire lifecycle. This means that on every render, the referenced object is the same one.

**Example:**

```jsx
const refContainer = useRef(initialValue);
```

No matter how many times the component re-renders, `refContainer` is the same object.

### 2. Changing `ref.current` does not cause the component to re-render

Unlike state variables, updating the value of `ref.current` does not cause the component to re-render. This makes `useRef` ideal for storing mutable values that do not affect the UI, such as timer IDs, external library instances, and so on.

**Example:**

```jsx
function Stopwatch() {
  const timerRef = useRef(null);

  function startTimer() {
    timerRef.current = setInterval(() => {
      // 更新计时器
    }, 1000);
  }

  function stopTimer() {
    clearInterval(timerRef.current);
  }
}
```

In this example, we use `timerRef` to store the return value of `setInterval` (that is, the timer ID), and clear the timer when needed.

### 3. Do not read or modify `ref.current` during rendering

Reading or modifying `ref.current` during rendering can lead to unpredictable behavior, because React expects the rendering process to be a pure function with no side effects. You should avoid using `ref` during rendering unless it is for initialization.

**Incorrect example:**

```jsx
function MyComponent() {
  const countRef = useRef(0);
  countRef.current++; // ❌ 不要在渲染过程中修改 ref

  return <div>{countRef.current}</div>;
}
```

### 4. Accessing DOM elements

One of the most common uses of `useRef` is to directly access DOM elements. We can assign the `ref` object to the `ref` attribute of a JSX element, and React will assign the corresponding DOM element to `ref.current` when the component mounts.

**Example:**

```jsx
function TextInputWithFocusButton() {
  const inputRef = useRef(null);

  function handleClick() {
    inputRef.current.focus();
  }

  return (
    <>
      <input ref={inputRef} type="text" />
      <button onClick={handleClick}>聚焦输入框</button>
    </>
  );
}
```

In this example, clicking the button calls `handleClick`, and then `inputRef.current.focus()` is used to focus the input box.

### 5. Avoid repeated creation during initialization

If you need to store a complex object or class instance in `useRef`, be careful to avoid creating a new instance on every render. You can initialize `ref.current` on the component's first render and keep it unchanged in subsequent renders.

**Example:**

```jsx
function VideoPlayerComponent() {
  const playerRef = useRef(null);

  if (playerRef.current === null) {
    playerRef.current = new VideoPlayer();
  }

  // 使用 playerRef.current
}
```

In this example, we create the `VideoPlayer` instance only when `playerRef.current` is `null`, avoiding the creation of a new instance on every render.

## DO

- **Storing mutable values**: You can use `useRef` to store any mutable value that needs to persist between renders, such as counters, timer IDs, external library instances, and so on.

  ```jsx
  const countRef = useRef(0);
  ```

- **Accessing DOM elements**: By assigning the `ref` object to the `ref` attribute of a JSX element, you can directly access the DOM element.

  ```jsx
  <input ref={inputRef} type="text" />
  ```

- **Reading and modifying `ref.current` in event handlers or side effects**: You can safely read and modify `ref.current` in event handler functions or `useEffect`.

  ```jsx
  useEffect(() => {
    ref.current = computeExpensiveValue();
  }, []);
  ```

## DONT DO


- **Do not read or modify `ref.current` during rendering**: This breaks the pure function nature of the component and leads to unpredictable behavior.

  ```jsx
  function MyComponent() {
    ref.current = someValue; // ❌ 不要在渲染过程中修改 ref
    return <div>{ref.current}</div>; // ❌ 不要在渲染过程中读取 ref
  }
  ```

- **Do not expect changing `ref.current` to trigger a re-render**: If you need to reflect a value's change in the UI, you should use the state variable `useState` instead of `useRef`.

- **Do not assign `ref` directly to a function component**: By default, you cannot use `ref` on a function component. If needed, you can use `React.forwardRef` to forward `ref`.

  ```jsx
  const MyInput = React.forwardRef((props, ref) => (
    <input ref={ref} {...props} />
  ));
  ```

## Examples

### 1. Counting clicks (no re-render needed)

```jsx
import { useRef } from 'react';

function ClickCounter() {
  const clickCount = useRef(0);

  function handleClick() {
    clickCount.current++;
    console.log(`按钮点击了${clickCount.current}次`);
  }

  return <button onClick={handleClick}>Click me</button>;
}
```

In this example, we use `useRef` to track the number of times the button has been clicked. Because this value does not need to be used for rendering, using `useRef` is more appropriate than `useState`.

### 2. Manipulating DOM elements

```jsx
import { useRef } from 'react';

function ScrollToTop() {
  const divRef = useRef(null);

  function handleScroll() {
    divRef.current.scrollTop = 0;
  }

  return (
    <div ref={divRef} style={{ height: '200px', overflow: 'scroll' }}>
      {/* 内容 */}
      <button onClick={handleScroll}>回到顶部</button>
    </div>
  );
}
```
{% endraw %}

In this example, we directly manipulate the scroll position of the `div` element to bring it back to the top.

### 3. Creating an object only once during initialization

```jsx
import { useRef } from 'react';

function ExpensiveComponent() {
  const dataRef = useRef(null);

  if (dataRef.current === null) {
    dataRef.current = computeExpensiveData();
  }

  // 使用 dataRef.current
}
```

By storing computationally intensive data in `useRef`, we avoid repeated computation on every render.

## Summary

`useRef` is a powerful Hook that allows us to store mutable values without triggering a re-render. When using `useRef`, note the following:

- **Do not read or modify `ref.current` during rendering**.

- **Changing `ref.current` does not trigger a re-render**, so it should not be used for values that need to be displayed in the UI.

- **It is suitable for storing mutable values that need to persist between renders**, such as timer IDs, external library instances, and so on.

- **It can be used to directly access DOM elements**, enabling operations such as manual focusing and scrolling.

By using `useRef` correctly, we can manage mutable values in components and improve the performance and readability of the code.
