## Process States

Process states are divided into five types: running, ready, blocked, created, and terminated, among which the three states of **running, ready, and blocked** are the **basic states of a process**.

Throughout the entire lifecycle of a process, it spends most of its time in the three basic states.

In the single-CPU case, only one process is in the running state at any given moment; in the multi-core CPU case, multiple processes may be in the running state.

### Created State and Ready State

When a process is being created, its state is the "created state"; at this stage, the operating system allocates resources for the process and initializes the PCB;

After the process creation is complete, it enters the "ready state";

A process in the **ready state** already **meets the conditions for running**, but because **there is no idle CPU**, it temporarily cannot run.

### Running State

There may be many processes in the system that are all in the ready state;

When the CPU is idle, the operating system selects a ready process and lets it run on the processor.

If **a process is currently running on the CPU**, then this process is in the "**running state**". The CPU executes the program corresponding to this process (executes the instruction sequence).

### Blocked State

While a process is running, it may request to **wait for the occurrence of some event (such as waiting for the allocation of some system resource, or waiting for a response from another process)**.

Before this event occurs, the process cannot continue executing; at this point, **the operating system takes this process off the CPU** and lets it enter the "**blocked state**".

When the CPU is idle, it will again select another "ready state" process to run on the CPU.

After that, if the resource is successfully allocated to the blocked process, that is, the event that the blocked process was waiting for has occurred, the operating system then transitions the process to the ready state.

### Terminated State

A process can execute the exit system call to request that the operating system terminate the process.
At this point, the process enters the "terminated state"; the operating system takes the process off the CPU and reclaims resources such as memory space, and finally also reclaims the process's PCB.

After the work of terminating the process is complete, the process disappears completely.

Note:
- The transition from blocked state to ready state is not something the process itself can control; it is a **passive behavior**.
- The transition from running state to blocked state is an **active behavior** made by the process itself.
- **A process cannot transition directly from the blocked state to the running state, nor can it transition directly from the ready state to the blocked state** (because entering the blocked state is actively requested by the process, and the process must necessarily be running to issue such a request).

## Process Organization Methods

In a process's PCB, there is a variable state that indicates the current state of the process. For example: 1 indicates the created state, 2 indicates the ready state, 3 indicates the running state...
In order to uniformly manage the various processes in the same state, the operating system organizes the PCBs of the various processes.

### Linked Method
In the linked method, the operating system divides PCBs into **multiple queues** according to process state; the operating system holds **pointers to each queue**.
