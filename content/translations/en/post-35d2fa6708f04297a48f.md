## Background of Threads

## Thread Implementation Methods

### User-Level Threads

<img src='\images\posts\操作系统-进程-用户级线程.jpg'
  style="
    display: block;
    margin-left: auto;
    margin-right: auto; 
    zoom:50%;" />

1. User-Level Threads (ULT) are implemented by applications through thread libraries, and all **thread management work** is the responsibility of the **application** (including thread switching);
2. In user-level threads, **thread switching** can be completed **in user mode**, without operating system intervention;
3. From the user's perspective, there are multiple threads. But from the operating system kernel's perspective, it is not aware of the existence of threads. **"User-level threads"** are simply **"the threads that can be seen from the user's perspective"**.

Advantages and disadvantages of user-level threads:
- Advantages: Switching of user-level threads can be completed in user space without switching to kernel mode, so the system overhead of thread management is small and efficiency is high;
- Disadvantages: When a user-level thread is blocked, the entire process will be blocked, and the degree of concurrency is not high. Multiple threads cannot run in parallel on a multi-core processor.

### Kernel-Level Threads

<img src='\images\posts\操作系统-进程-内核级线程.jpg'
  style="
    display: block;
    margin-left: auto;
    margin-right: auto; 
    zoom:50%;" />

1. The **management work of Kernel-Level Threads (KLT)** is completed by the **operating system kernel**;
2. Thread scheduling, switching, and other work are all handled by the kernel, so **switching of kernel-level threads** must necessarily be completed in **kernel mode**;
3. The operating system establishes a corresponding TCB (Thread Control Block) for each kernel-level thread and manages threads through the TCB. **"Kernel-level threads"** are simply **"the threads that can be seen from the operating system kernel's perspective"**.

Advantages and disadvantages of kernel-level threads:
- Advantages: When one thread is blocked, other threads can continue to execute, and the concurrency capability is strong. Multiple threads can execute in parallel on a multi-core processor;
- Disadvantages: One user process will occupy multiple kernel-level threads, and thread switching is completed by the operating system kernel and requires switching to kernel mode, so the cost of thread management is high and the overhead is large.

## Multithreading Models

In systems that support kernel-level threads, several multithreading models can be classified according to the mapping relationship between user-level threads and kernel-level threads.

### One-to-One Model

<img src='\images\posts\操作系统-进程-一对一模型.jpg'
  style="
    display: block;
    margin-left: auto;
    margin-right: auto; 
    zoom:50%;" />

One-to-one model: One user-level thread maps to one kernel-level thread, and each user process has the same number of kernel-level threads as user-level threads.
- Advantages: When one thread is blocked, other threads can continue to execute, and the concurrency capability is strong. Multiple threads can execute in parallel on a multi-core processor.
- Disadvantages: One user process will occupy multiple kernel-level threads, and thread switching is completed by the operating system kernel and requires switching to kernel mode, so the cost of thread management is high and the overhead is large.

### Many-to-One Model

<img src='\images\posts\操作系统-进程-多对一模型.jpg'
  style="
    display: block;
    margin-left: auto;
    margin-right: auto; 
    zoom:50%;" />

Many-to-one model: Multiple user-level threads map to one kernel-level thread, and a process is allocated only one kernel-level thread.
- Advantages: Switching of user-level threads can be completed in user space without switching to kernel mode, so the system overhead of thread management is small and efficiency is high
- Disadvantages: When a user-level thread is blocked, the entire process will be blocked, and the degree of concurrency is not high. Multiple threads cannot run in parallel on a multi-core processor
- Note: The operating system only "sees" kernel-level threads, so only **kernel-level threads are the unit of processor allocation**.


### Many-to-Many Model

<img src='\images\posts\操作系统-进程-多对多模型.jpg'
  style="
    display: block;
    margin-left: auto;
    margin-right: auto; 
    zoom:50%;" />

Many-to-many model: **n user-level threads map to m kernel-level threads (n>=m)**. Each user process corresponds to m kernel-level threads.

It overcomes the disadvantage of the many-to-one model's low concurrency (one blocked means all blocked), and also overcomes the disadvantage of the one-to-one model in which one user process occupies too many kernel-level threads and the overhead is too large.

It can be understood this way: user-level threads are the carriers of "code logic"; kernel-level threads are the carriers of "execution opportunities". **Kernel-level threads are the unit of processor allocation**. In a multi-core CPU environment, the process in the figure above can be allocated at most two cores.
A piece of "code logic" can be executed by the CPU only after it obtains an "execution opportunity".
A kernel-level thread can run the code of any user-level thread that has a mapping relationship with it, and only when the code logic running in both kernel-level threads is blocked will this process be blocked.
