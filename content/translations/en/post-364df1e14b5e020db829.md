### DO

1. **Call components using JSX**:
   - Components can only be used in JSX, and React automatically handles component rendering. **Do not call component functions directly**; instead, let React manage component calls through JSX.
   - Example:
     ```js
     function BlogPost() {
       return <Layout><Article /></Layout>; // ✅ 正确：通过 JSX 使用组件
     }
     ```

2. **Hooks should only be called inside components or Hooks**:
   - **Hooks can only be called in function components or custom Hooks**, and React is responsible for managing these calls. Do not pass Hooks as ordinary values or use them elsewhere.
   - Example:
     ```js
     function useDataWithLogging() {
       const data = useData(); // ✅ 正确：在自定义 Hook 中调用 Hook
       // 其他逻辑
       return data;
     }
     ```

3. **Create new Hook versions to extend functionality**:
   - If you need to extend a Hook's functionality, **you can create a new Hook** and inline the required logic into that Hook, rather than dynamically changing an existing Hook.
   - Example:
     ```js
     function ChatInput() {
       const data = useDataWithLogging(); // ✅ Good: Create a new version of the Hook
     }
     
     function useDataWithLogging() {
       // ... Create a new version of the Hook and inline the logic here
     }
     ```
   
4. **Inline Hook calls**:
   - **Embed Hook calls directly inside components**; do not pass Hooks as `props`. This makes components easier to understand and debug.
   - Example:
     ```js
     function ChatInput() {
       return <Button />
     }
     
     function Button() {
       const data = useDataWithLogging(); // ✅ Good: Use the Hook directly
     }
     
     function useDataWithLogging() {
       // If there's any conditional logic to change the Hook's behavior, it should be inlined into
       // the Hook
     }
     ```



### DONT DO

1. **Do not call component functions directly**:
   - Components can only be rendered through JSX; **do not call them as ordinary functions**. Calling components directly may break React's optimization mechanisms and violate the Rules of Hooks.
   - Incorrect example:
     ```js
     function BlogPost() {
       return <Layout>{Article()}</Layout>; // ❌ 错误：直接调用组件函数
     }
     ```

2. **Do not pass Hooks as regular values**:
   - **Hooks should not be passed as ordinary values**; instead, they should be called directly inside components or Hooks. Passing Hooks as values breaks React's automatic optimizations and makes debugging difficult.
   - Incorrect example:
     ```js
     function ChatInput() {
       return <Button useData={useDataWithLogging} />; // ❌ 错误：将 Hook 作为 props 传递
     }
     ```

3. **Do not dynamically change Hooks**:
   - **Hooks should remain static and should not be changed dynamically**. Do not create higher-order Hooks or dynamically modify Hooks during rendering; instead, define Hook behavior statically.
   - Incorrect example:
     ```js
     function ChatInput() {
       const useDataWithLogging = withLogging(useData); // ❌ 错误：动态创建 Hook
       const data = useDataWithLogging();
     }
     ```

4. **Do not use Hooks dynamically**:
   - **Do not call Hooks dynamically based on conditions**; React requires Hooks to be called in the same order on every render. Using Hooks dynamically leads to unexpected errors and complicated debugging.
   - Incorrect example:
     ```js
     function Button() {
       if (someCondition) {
         const data = useDataWithLogging(); // ❌ 错误：动态调用 Hook
       }
       return <button>{data}</button>;
     }
     ```

### Summary

- **What you can do**: Call components through JSX; call Hooks inside components or Hooks; create new Hook versions to extend functionality; inline Hook calls in components.
- **What you cannot do**: Do not call component functions directly; do not pass Hooks as ordinary values; do not dynamically change Hooks; do not dynamically call Hooks under conditions.

Through these rules, React can manage the rendering process of components and Hooks, ensuring that application performance optimization and debugging are more efficient.

More about the Rules of Hooks: https://react.dev/reference/rules/rules-of-hooks
