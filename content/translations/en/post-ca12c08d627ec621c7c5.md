## Problem Description
There are two groups of concurrent processes, readers and writers, sharing a single file.
When two or more reader processes access the shared data simultaneously, no side effects occur, but if a writer process and another process (either a reader or a writer) access the shared data simultaneously, it may cause data inconsistency errors.
Therefore, the requirements are:
1. **Multiple readers** are allowed to perform read operations on the file simultaneously;
2. **Only one writer** is allowed to write information to the file;
3. No writer is **allowed to work before completing its write operation, nor are other readers or writers**;
4. Before a writer **performs a write operation, all existing readers and writers should be made to exit**.

Note: Unlike the consumer process, the reader process does not clear the data after reading it, nor does it change the data. Therefore, multiple readers can access the shared data simultaneously.

## Implementation Principle
Two types of processes: writer process, reader process

Mutual exclusion relationships:
- There is a mutual exclusion relationship between writer process and writer process, and between writer process and reader process.
- There is no mutual exclusion problem between reader process and reader process.

## Code Implementation
### Implementing Mutually Exclusive Access

We can set a semaphore rw to guarantee the mutual exclusion relationships between writer process and reader process, and between writer process and writer process:

Writer:
```c
P(rw)
写文件;
V(rw)
```

Reader:
```c
P(rw)
读文件;
V(rw)
```

### Ensuring Reader Processes Do Not Block Each Other

To prevent the semaphore rw from blocking multiple reader processes during the file reading process, the following code can make the locking process the responsibility of **only the first reader process**.
Subsequent reader processes no longer need to acquire the lock to read the file contents.
And **the last reader process is responsible for the unlocking process**.

Reader:
```c 
if(count == 1)  // 由第一个读进程负责
    P(rw);      // 读之前加锁
count++;        // 访问文件的读进程数+1
读文件;
count--;        // 访问文件的读进程数-1
if(count == 0)  // 由最后一个读进程负责
    V(rw);      // 读完了解锁
```

If two reader processes execute concurrently, then when count=0, both processes may satisfy the if condition and both execute `P(rw)`, thereby blocking the second reader process.
The reason for the above problem is that the check and assignment of the count variable cannot be completed in one atomic step, so another mutual exclusion semaphore can be set to ensure that each reader process's access to count is mutually exclusive.

**At this point, count is a critical resource, and another semaphore mutex needs to be added to guarantee the atomicity of its operations.**

Reader:
```c
P(mutex);       // 各读进程互斥访问count
if(count == 1)  // 由第一个读进程负责
    P(rw);      // 读之前加锁
count++;        // 访问文件的读进程数+1
V(mutex);       // 访问完count解锁
读文件;
P(mutex);       // 各读进程互斥访问count
count--;        // 访问文件的读进程数-1
if(count == 0)  // 由最后一个读进程负责
    V(rw);      // 读完了解锁
V(mutex);       // 访问完count解锁
```

### Implementing Writer Priority

The previous implementation still has a potential problem: as long as a reader process is still reading, the writer process must remain blocked and waiting, and may "starve".
Therefore, in this algorithm, reader processes have priority.
To solve this problem, another semaphore w can be added to prevent writer starvation.

```c 
// 信号量设置
semaphore rw = 1;       //用于实现对共享文件的互斥访问
int count = 0;          //记录当前有几个读进程在访问文件
semaphore mutex = 1;    //用于保证对count变量的互斥访问
semaphore w = 1;        //用于实现"写优先"

Writer() {
    while(1) {
        P(w);
        P(rw);          // 写之前加锁
        写文件;
        V(rw);          // 写之后解锁
        V(w);
    }
}

Reader() {
    while(1) {
        P(w);
        P(mutex);       // 各读进程互斥访问count
        if(count == 1)  // 由第一个读进程负责
            P(rw);      // 读之前加锁
        count++;        // 访问文件的读进程数+1
        V(mutex);       // 访问完count解锁
        V(w);
        读文件;
        P(mutex);       // 各读进程互斥访问count
        count--;        // 访问文件的读进程数-1
        if(count == 0)  // 由最后一个读进程负责
            V(rw);      // 读完了解锁
        V(mutex);       // 访问完count解锁
    }
}

```

Analyze the following situations of concurrent execution of P(w):
- Reader 1 -> Writer 1 -> Reader 2
- Writer 1 -> Reader 1 -> Writer 2

In this algorithm, multiple readers entering consecutively can read the file simultaneously; writers and other processes cannot access the file simultaneously; writers will not starve, but it is not truly "writer priority" either; rather, it is the **relatively fair first-come, first-served principle.**
This algorithm is also called the "read-write fair method".

## Summary

The reader-writer problem provides us with a reference approach for solving complex mutual exclusion problems.

Its **core idea** is to set up a **counter count** to record the number of reader processes currently accessing the shared file.
We can use the value of count to determine whether the currently entering process is the first/last reader process, and thus handle it differently.

In addition, the fact that the check and assignment of the count variable cannot be completed in one atomic step causes some errors. If **"completing in one atomic step" needs to be achieved, it is natural to think of using a mutual exclusion semaphore.**

Finally, also carefully appreciate how we solve the **"writer process starvation"** problem.
