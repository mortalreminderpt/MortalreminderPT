### **Role of the Transport Layer**
To provide efficient, reliable, and cost-effective data transmission services for processes at the application layer, while remaining independent of the physical layer or data link layer.

This goal is achieved by invoking the services provided by the network layer.



### **Transport Protocol Data Unit**
- An abstract representation of messages sent to and from the transport entity.
- **Transport Protocol Data Unit (TPDU)** = Segment.
- Encapsulate segments into packets and frames.



### **Three-Way Handshake**
The purpose of the three-way handshake is to protect communication from the following problems:
- **Duplicate CR (Connect Request)**: Duplicate connection requests.
- **Duplicate CR and DATA**: Duplicate connection requests and data. Identical data combined with an incorrect ACK will be rejected.

#### What is the three-way handshake?
Suppose you want to play a game with a friend. You need to make sure the other party is ready, and the other party also needs to confirm that you are ready. The specific process of the three-way handshake is as follows:
1. You signal to the other party: "Are you ready?"
2. The other party responds: "I'm ready, and you?"
3. You confirm receipt of the other party's reply: "I'm ready too, let's start!"

Through back-and-forth confirmation, both parties are ensured to be ready.

#### Why can't a two-way handshake be used?
If only a two-way handshake is used, misunderstandings may occur. For example, delays or packet loss may cause both communicating parties to mistakenly believe that the other is not ready, leading to communication confusion.

#### The problem in the figure
In the figure, duplicate old messages (old duplicate messages) may appear, which can cause misunderstandings between the communicating parties. For example:
- A duplicate connection request is mistaken for a new message.
- The three-way handshake can avoid this misunderstanding, because each communication requires a new message confirmation.

#### Example
If a two-way handshake is used instead of a three-way handshake, deadlock may occur. For example:
- A receives a packet and acknowledges it, but the acknowledgement message is lost.
- Both A and B are in the open state, but their sequence numbers differ, and communication reaches an impasse.
A timeout mechanism must be introduced to avoid deadlock.



### **Connection Release**
1. **Asymmetric Disconnection**: Either party can issue a DISCONNECT command, causing bidirectional transmission to end.
   - This may cause data loss.
2. **Symmetric Disconnection**: Both parties each close transmission in one direction (four-way handshake), allowing the receive mode to be maintained more flexibly.

Normal disconnection sequence:
- Host 1 issues a DR (Disconnect Request), and both parties acknowledge each other's DR.

#### Example
If the initial DR and all subsequent retransmissions are lost, Host 1 will time out and release the connection, while Host 2 may remain in the connected state, resulting in data loss and wasted resources.



### **Port & Socket**
1. The application layer and transport layer need to specify the remote process for the connection.
2. At the transport layer, addressing usually uses **Transport Service Access Points (TSAPs)**.
   - On the Internet, TSAPs are usually called **Ports** (such as port 80).
3. At the network layer, addressing usually uses **Network Service Access Points (NSAPs)**.
   - On the Internet, NSAPs usually correspond to **IP addresses**.



### **User Datagram Protocol (UDP)**
1. Provides a connectionless protocol that allows applications to send encapsulated IP datagrams.
2. **Advantages**:
   - Provides an IP interface that supports multiplexing, improving transmission efficiency.
3. **Disadvantages**:
   - Does not support flow control, error control, or retransmission of bad segments.

#### Example
UDP is similar to sending a courier package:
- **Datagrams**: Data is split into small pieces for transmission.
- **Connectionless**: Send directly without establishing a connection.
- **High efficiency**: Suitable for scenarios with high speed requirements, such as live streaming and online games.



### **Remote Procedure Call (RPC)**
1. **RPC** is an application of **UDP** (there is also RPC based on TCP).
2. Core idea: Make remote calls look like local calls.
3. By binding **Stubs** on the client and server sides, the effect of a "connection" is achieved.



### **Transmission Control Protocol (TCP)**
#### Characteristics of TCP connections
1. **Full Duplex**: Supports simultaneous bidirectional data transmission.
2. **Point to Point**: An exact sender and receiver pair.
3. **Byte Streams**: Data flows in units of bytes, without preserving message boundaries.
4. **Buffer Capable**:
   - Can choose to buffer data or send it immediately.
   - **URGENT flag**: Send immediately.
   - **PUSH flag**: Prohibit delay.

#### TCP Header field analysis
1. **Source Port and Destination Port**: Source port and destination port, used to identify the sender and receiver.
2. **Sequence Number**: Used to mark the order of packets.
3. **Acknowledgement Number**: Marks the packets that the receiver has received.
4. **Flags**: Switches that control data behavior (such as SYN, ACK, FIN).
5. **Window Size**: The receiver's window size, indicating the amount of data that can be received at one time.
6. **Checksum**: Used to check data integrity.
7. **Urgent Pointer**: Indicates urgent data.
8. **Options and Data**: Optional items and data content.



### **TCP Window Management**
- TCP ensures correct receipt of segments through an acknowledgement mechanism.
- The receiver adjusts the window size according to buffer space.



### **Congestion Control**
- **Slow Start**: In the initial stage, gradually probe the degree of network congestion and gradually increase the sending window.
- **Additive Increase**: Slowly increase the sending window.
- **Fast Recovery**: When packet loss occurs, continue increasing the window through fast recovery.



### **QoS**
QoS requirements of different application layers:
1. **Over-Provisioning**: Requires sufficient buffers, router CPU, and bandwidth.
2. **Buffering**: Buffering the received data stream reduces jitter but increases latency.
3. **Traffic Shaping**: Controls transmission rate and burst traffic (such as **Leaky Bucket**).
4. **Admission Control**: Routers decide whether to accept based on traffic conditions.



### **Flow Control vs. Congestion Control**
1. **Flow Control**: A point-to-point traffic problem that prevents the sender from being faster than the receiver.
2. **Congestion Control**: Involves the overall traffic-carrying capacity of the subnet.
