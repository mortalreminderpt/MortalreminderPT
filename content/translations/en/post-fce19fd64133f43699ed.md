## Overlay Technology
Early computers had very little memory. For example, the first PC launched by IBM supported a maximum memory size of only 1MB.
As a result, situations where the memory size was insufficient often occurred.

Later, people introduced **overlay technology** to **solve the problem that "the program size exceeds the total physical memory"**.

The idea of overlay technology: **divide the program into multiple segments** (multiple modules). Commonly used segments reside in memory permanently, while infrequently used segments are loaded into memory when needed.

Memory is divided into **one "fixed area"** and **several "overlay areas"**:
- Segments that need to reside in memory permanently are placed in the "fixed area" and are not swapped out after being loaded (unless execution ends);
- Infrequently used segments are placed in "overlay areas"; they are loaded into memory when needed and swapped out of memory when not needed.

Memory overlay technology, according to its own logical structure, allows program segments that cannot be accessed at the same time to share the same overlay area.

**The overlay structure must be declared by the programmer**, and the operating system performs automatic overlaying. Disadvantage: **it is not transparent to users**, which increases the programming burden on users.
Overlay technology was used only in early operating systems and has now become history.

## Swapping Technology
The design idea of swapping (exchange) technology:
When memory space is tight, the system **temporarily swaps some processes in memory out to external storage**, and **swaps some processes in external storage that already have the conditions to run into memory**. (Processes are dynamically scheduled between memory and disk; intermediate scheduling)

### Questions

- Where in external storage (disk) should swapped-out processes be saved?

In operating systems with swapping functionality, disk space is usually divided into two parts: the **file area** and the **swap area**.
**The file area is mainly used to store files**, and mainly **pursues storage space utilization**, so the management of file area space **adopts discrete allocation**;
**The swap area** occupies only a **small part** of disk space, and **the data of swapped-out processes is stored in the swap area**.
Because the speed of swapping directly affects the overall speed of the system, **the management of swap area space mainly pursues swap-in and swap-out speed, so the swap area usually adopts continuous allocation**.
In short, **the I/O speed of the swap area is faster than that of the file area**.

- When should swapping occur?

Swapping usually occurs when many processes are running and memory is tight, and pauses when the system load decreases.
For example, if page faults frequently occur when many processes are running, it indicates that memory is tight, and some processes can be swapped out at this time;
if the page fault rate drops significantly, swapping out can be paused.

- Which processes should be swapped out?

Blocked processes can be swapped out first; processes with lower priority can be swapped out;
to prevent low-priority processes from being swapped out again soon after being loaded into memory, some systems also consider the residence time of processes in memory.
(Note: **The PCB resides in memory permanently** and will not be swapped out to external storage)

## Differences Between Overlay and Swapping
- Overlay occurs within the same program or process;
- Swapping occurs between different processes (or jobs).
